# 5.8 The Stack :: Systems

## نقاش معمّق

### أدنى طبقة صريحة

**Systems** هي أدنى طبقة صريحة في Stack. تمثل هذه الطبقة بيئة الحوسبة التي توفر الخدمات والأجهزة والعمليات الكامنة اللازمة لتسليم output واستقبال interaction. حيث يحدد Layer 2 السياق المحدود الذي يمر عبره output وinteraction، يمثل Layer 1 البيئة الأوسع التي تجعل ذلك السياق ممكنًا.

لا ينبغي فهم system على أنه نظام تشغيل مكتبي فقط. في نموذج CatalystUI، system هو مجموعة منظمة من العمليات وقدرات المنصة التي تدعم الواجهة في runtime. قد يكون نظام تشغيل تقليديًا، أو embedded environment، أو console، أو browser runtime، أو hardware platform، أو سياق حوسبة مُدار آخر. السمة المحددة ليست فئة المنتج. السمة المحددة هي أن system يوفر lower-level capabilities التي تستطيع الواجهة العمل فعليًا من خلالها.

### بيئة التشغيل

توفر طبقة System بيئة التنفيذ المحيطة لـ Stack الصريح. قد تدير hardware access أو input devices أو output devices أو drivers أو permissions أو scheduling أو memory أو files أو processes أو windows أو channels أو خدمات أخرى على مستوى platform. تختلف هذه التفاصيل كثيرًا بين التنفيذات، لكنها كلها تخدم الدور المفهومي نفسه: تسمح للواجهة بالاتصال بالقدرات الفعلية للآلة أو نظام المعلومات.

هذا يجعل Layer 1 مختلفًا عن Layer 2. Window هي سياق system-facing محدود تستخدمه الواجهة. System هو البيئة الأوسع التي تنشئ ذلك السياق وتملكه وتتعرف إليه وتقيّده وتخدمه. توفر window نقطة اتصال محددة؛ ويوفر system العالم الذي يوجد فيه ذلك الاتصال.

لذلك ليست طبقة System أساسًا سلبيًا فقط. إنها تشارك بنشاط في دورة الواجهة. إنها تسلّم output المصيّر نحو أجهزة فيزيائية أو منطقية، وتستقبل input من تلك الأجهزة، وتطبق قواعد المنصة، وتكشف العمليات التي تعتمد عليها الطبقات العليا. قد يصف Stack تدفق الواجهة، لكن system يوفّر الأرض التشغيلية تحت ذلك التدفق.

### العلاقة مع Windows

Systems وWindows مترابطة بشدة، لكنها ليست الطبقة نفسها. تتلقى window ‏output مصيّرًا من Layer 3 وتوفر delivery context محدودًا. يتلقى system ذلك windowed output وينفذ العمل الأدنى مستوى اللازم لتسليمه عبر الأجهزة أو الخدمات المتاحة.

في التدفق من الأعلى إلى الأسفل، تمرر window ‏output إلى system. ثم يتولى system مسار التسليم الفعلي: إرسال visual output إلى شاشة، أو audio output إلى جهاز صوت، أو tactile output إلى haptic device، أو text output إلى terminal، أو شكل output آخر إلى channel المناسب له. تحدد window أين ينتمي output؛ ويحمله system إلى البيئة القادرة على جعله قابلًا للإدراك.

في التدفق من الأسفل إلى الأعلى، يتلقى system أو يكتشف interaction من الجانب الإنساني للواجهة. قد يأتي ذلك عبر keyboard أو pointer أو touchscreen أو microphone أو controller أو sensor أو button أو input path آخر. يحوّل system ذلك النشاط الفيزيائي أو device-level إلى system-level signal يمكن ربطه بـ window وتمريره صعودًا عبر Stack.

### تسليم output

طبقة System هي المرحلة الصريحة الأخيرة في التدفق من الأعلى إلى الأسفل. بحلول وقت وصول output إلى Layer 1، تكون الطبقات العليا قد فسرت التمثيل الأصلي، وشكلت كائنات واجهة قابلة للاستخدام، ونظمتها في سياق تشغيل حالي، وصيّرت ذلك السياق في شكل جاهز لـ output، ومررته عبر window. الآن ينفذ system ‏platform-level work اللازم لجعل ذلك output متاحًا لـ Human Interface.

هذا لا يعني أن system نفسه هو إدراك المستخدم. المستخدم لا يدرك نظام التشغيل مباشرة. يدرك المستخدم النتيجة الفيزيائية أو الحسية المتاحة عبر الأجهزة والقنوات التي يديرها system. لذلك يبقى Layer 1 داخل العملية في جانب الحاسوب، بينما يقع Human Interface الضمني وراءه بصفته مستلم output.

يحافظ هذا التمييز على دقة النموذج. يستطيع system إنتاج ضوء عبر شاشة، أو صوت عبر مكبرات، أو اهتزاز عبر محرك، أو نتيجة أخرى قابلة للإدراك عبر جهاز أو خدمة. يوفر system آلية التسليم الصريحة الأخيرة؛ ويتلقى Human Interface النتيجة ويدركها.

### أصل interaction

طبقة System هي أيضًا أول مرحلة صريحة في التدفق من الأسفل إلى الأعلى. ينفذ المستخدم فعلًا خارج Stack الصريح، لكن system هو المكان الذي يصبح فيه ذلك الفعل متاحًا للواجهة المُمثلة في النموذج بصفته interaction input. ينتمي الفعل الإنساني نفسه إلى Human Interface الضمني. يتلقى system أثر ذلك الفعل عبر input path مدعوم ويبدأ تحويله إلى شيء يستطيع Stack معالجته.

لهذا يرتبط system ارتباطًا وثيقًا بـ interaction. يجب أن تتلقى بيئة الحوسبة أولًا ضغطة مفتاح فيزيائية أو حركة مؤشر أو touch gesture أو spoken input أو controller signal أو sensor change قبل أن تتمكن طبقات الواجهة العليا من الاستجابة. لا يحدد system عادة المعنى النهائي لذلك interaction. إنه يحدد أن شيئًا ما حدث، ويوفر device أو platform context ذا صلة، ويمرر interaction نحو window المناسبة.

من هناك يستطيع interaction أن يسافر صعودًا عبر Stack. تربطه window بسياق محدود، وقد يساعد renderer على ترجمته أو مطابقته، وقد يوجهه graph وframe، وقد يعالجه control المناسب في النهاية. يبدأ system مسار العودة الصريح، لكن معنى الفعل يُحل أعلى في Stack.

### قواعد المنصة وقيودها

Systems مهمة لأن كل واجهة تعمل ضمن قيود. قد يحدد system ما الأجهزة المتاحة، وكيف تُنشأ windows، وكيف يُسلّم input، وكيف تُمنح permissions، وكيف تتصرف output channels، وما resources التي يمكن الوصول إليها، وما operations المدعومة. تشكل هذه القيود ما تستطيع بقية Stack فعله.

مع ذلك، يفصل CatalystUI هذه platform concerns عن نموذج الواجهة العلوي. لا ينبغي أن تحتاج components إلى فهم كل driver أو قاعدة operating system مباشرة. ولا ينبغي أن تحتاج renderers إلى إدارة كل hardware detail. ولا ينبغي أن تمثل windows المنصة كلها. يوفر Layer 1 مكانًا واضحًا لـ system-level behavior، مما يسمح للطبقات العليا بالبقاء مركزة على التفسير وقابلية الاستخدام والتنظيم والتحويل.

يسمح هذا الفصل أيضًا بتطبيق النموذج عبر بيئات مختلفة. قد تمتلك desktop application أو mobile app أو embedded device أو browser-based interface أو command-line tool أو specialized hardware system قواعد platform مختلفة، لكن كلًا منها ما يزال يحتاج إلى طبقة system توفر بيئة التشغيل تحت الواجهة.

### العلاقة مع Human Interface

تقع Systems مباشرة فوق **Human Interface** الضمني. هذا يعني أن Layer 1 هو آخر طبقة صريحة قبل أن يغادر output التدفق المُمثل في جانب الحاسوب، وأول طبقة صريحة بعد دخول فعل المستخدم إليه. لذلك system هو الحد بين بيئة الحوسبة المُدارة والإنسان الذي يدرك ويتصرف.

هذا الحد أساسي. يستطيع النموذج وصف كيف يرسل system ‏output نحو جهاز، لكنه لا يضع نموذجًا مباشرًا للتجربة الحسية للمستخدم أو بيولوجيته أو انتباهه أو عاطفته أو تفسيره. وبالمثل، يستطيع النموذج وصف كيف يستقبل system ‏input signal، لكنه لا يضع نموذجًا مباشرًا للعملية الإنسانية الكاملة التي أنتجت الفعل. هذه الاهتمامات تنتمي إلى Human Interface الضمني.

بوضع Systems في Layer 1، يحدد Stack بوضوح أدنى نقطة صريحة يمكن وصف العملية في جانب الحاسوب عندها قبل العبور إلى الإدراك والفعل الإنسانيين.

### لماذا تهمّ الطبقة

تجعل Systems ‏Stack متجذرًا في التشغيل الحقيقي. من دون هذه الطبقة، سيصف النموذج rendering وwindows كما لو أن تسليم output واستقبال input يحدثان تلقائيًا. عمليًا، تعتمد كل واجهة على بيئة كامنة تدير الأجهزة والموارد والصلاحيات والتنفيذ وplatform behavior.

بفصل Systems عن Windows وHuman Interface، يحافظ النموذج على حد نهائي نظيف. توفر Windows السياق المحدود لـ output وinteraction. وتوفر Systems بيئة التشغيل الكامنة التي تسلّم output وتستقبل input. ويدرك Human Interface ‏output وينتج action. يسمح هذا التمييز لـ CatalystUI بوصف الواجهات عبر platforms وdomains من دون اختزال system إلى operating system واحد أو device محدد أو visual display model.
