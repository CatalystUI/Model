# 5.9 The Stack :: Human Interface

## نقاش معمّق

### الحد الإنساني الضمني

**Human Interface** هو الحد السفلي الضمني في Stack. إنه يمثل المستخدم: الشخص الذي يتلقى output قابلًا للإدراك من system وينتج أفعالًا قد تصبح interaction input. بعبارة أبسط، هذه الطبقة هي أنت.

قد يبدو ذلك واضحًا، لكنه مهم. يوجد Stack لوصف عملية التواصل بين المستخدم ونظام معلومات. إذا كان Data Storage يشرح الحد الذي يمكن أن يدخل عنده المحتوى المحتفَظ به إلى التدفق النشط أو يخرج منه، فإن Human Interface يشرح الحد المقابل: المكان الذي يصبح فيه computer output أخيرًا جزءًا من التجربة الإنسانية، وحيث يبدأ الفعل الإنساني مسار العودة إلى system.

Human Interface ضمني لأن النموذج لا يمثل مباشرة جسد المستخدم أو عقله أو انتباهه أو عواطفه أو حواسه أو نواياه أو ذكرياته أو اختياراته. يستطيع CatalystUI وصف كيف يسلّم system ‏output نحو مستخدم، وكيف يصبح فعل المستخدم interaction input، لكنه لا يدّعي نمذجة الإنسان كاملًا. سيكون ذلك طموحًا قليلًا. ومخيفًا أيضًا. Stack قوي، لكنه لا يحتاج إلى أن يصبح كتاب علم نفس ملحقًا به renderer.

### مستلم output القابل للإدراك

في التدفق من الأعلى إلى الأسفل، يكون Human Interface مستلم output القابل للإدراك. تتحرك Digital Data عبر Stack الصريح، وتصبح مفسَّرة ومشكّلة ومنظمة ومصيّرة ومسلّمة عبر window ومحمولة بواسطة system حتى يمكن أخيرًا إدراكها. عندما يصل ذلك output إلى حواس المستخدم، يكون Stack الصريح قد أكمل مساره الهابط.

هذا لا يعني أن المستخدم يتلقى Digital Data مباشرة. فالإنسان لا يدرك بطبيعته الآحاد والأصفار أو memory buffers أو draw calls أو audio samples أو system events. يدرك المستخدم نتيجة عمل system: الضوء أو الصوت أو الاهتزاز أو الحركة أو النص أو التغير المكاني أو شكلًا آخر من output الحسي. Human Interface هو المكان الذي يتوقف فيه output عن كونه مجرد شيء مسلّم ويبدأ بأن يُختبر.

يحافظ هذا التمييز على صدق النموذج. يستطيع system تقديم output، لكنه لا يستطيع فرض الفهم. قد تعرض شاشة زرًا، وقد يشغل مكبر صوتًا، وقد يهتز جهاز، لكن المستخدم ما يزال بحاجة إلى إدراك تلك النتيجة وتفسيرها كإنسان. يعترف النموذج بهذا الحد من دون محاولة تعريف كل عامل شخصي أو بيولوجي أو سياقي. بعبارة أخرى: يستطيع CatalystUI إيصال output إلى الإنسان. لا يستطيع جعل الإنسان يتوقف عن تجاهل الإشعار. للأسف.

### مصدر interaction

في التدفق من الأسفل إلى الأعلى، يكون Human Interface مصدر الفعل. يرى المستخدم ويسمع ويشعر ويفهم ويتفاعل ويقرر ثم يفعل شيئًا. قد يكون ذلك الفعل ضغط مفتاح، أو تحريك مؤشر، أو لمس شاشة، أو قول أمر، أو تدوير مقبض، أو المرور عبر حقل حساس، أو أداء سلوك آخر يستطيع system استلامه.

يبدأ الفعل نفسه خارج Stack الصريح. لا يصف النموذج مباشرة العملية الداخلية الكاملة التي قادت المستخدم إلى الفعل. يبدأ فقط في نمذجة مسار العودة عندما يتلقى system أثر ذلك الفعل. في تلك النقطة، يصبح الفعل interaction input ويدخل Layer 1: Systems، حيث يمكن تمريره صعودًا عبر Stack.

يحافظ هذا على تمييز نظيف بين **human action** و**system interaction**. Human action هو ما يفعله المستخدم. Interaction input هو ما يستلمه system من ذلك الفعل. هما مرتبطان بقوة، لكنهما غير متطابقين. قد يقصد شخص النقر على شيء وينقر على آخر بالخطأ، أو يلمس مفتاحًا أثناء محاولته الوصول إلى شيء آخر. قد يستلم system كليهما، لكن واحدًا منهما فقط غالبًا سيكون تعبيرًا ذا معنى عن قصد المستخدم. إلا إذا كان input العرضي هو الهدف، وفي هذه الحالة تهانينا: دخلت الواجهة مرحلة تجريبية جدًا.

### لماذا الطبقة ضمنية

Human Interface ضمني للسبب نفسه الذي يجعل Data Storage ضمنيًا: إنه مطلوب في التدفق، لكنه لا يُنمذج مباشرة كطبقة تحويل صريحة. يعتمد Stack على المستخدم، لكنه لا يحول المستخدم. لا يحلل المستخدم، ولا يصيّر المستخدم، ولا يكيّف المستخدم، ولا يخزّن المستخدم كـ component. وهذا على الأرجح للأفضل.

بدلًا من ذلك، يعامل النموذج Human Interface كحد حي حول النهاية السفلى لـ system. يستطيع Stack الصريح وصف كيف يُعد output ويُسلّم، ويستطيع وصف كيف يسافر interaction المستلم صعودًا. لكنه يتوقف قبل ادعاء الملكية على التجربة الإنسانية نفسها.

هذا الحد مهم خصوصًا لأن المستخدم ليس مجرد جهاز آخر. توفر شاشة visual output. وتوفر لوحة مفاتيح input signals. أما المستخدم فيدرك ويفسر ويختار ويستجيب ويسيء الفهم ويتعلم ويتردد ويرتكب أخطاء، وأحيانًا ينقر الزر الخطأ بثقة كاملة. ينبغي للنموذج أن يحترم هذا الاختلاف. لذلك يوجد Human Interface لأن Stack مبني للتواصل الإنساني، لكنه ضمني لأن الإنسان ليس جزءًا من عملية التحويل في جانب الآلة.

### الإدراك والقصد

يكمل Human Interface دورة التواصل بربط الإدراك والقصد. في اتجاه، يوفر system شيئًا قابلًا للإدراك. وفي الاتجاه الآخر، يستجيب المستخدم بفعل. هذا يخلق الحلقة الحوارية في مركز CatalystUI: يتكلم system عبر output، ويستجيب المستخدم عبر interaction، ويعالج system تلك الاستجابة لمواصلة التبادل.

لهذا لا يمكن اختزال Human Interface إلى input devices. قد تساعد keyboard أو mouse أو touchscreen أو microphone أو camera أو controller في التقاط interaction، لكن أيًا منها ليس المستخدم. إنها مسارات system-accessible يمكن أن يدخل عبرها فعل المستخدم إلى Stack. Human Interface هو الشخص الذي يمنح إدراكه وقصده تلك الإشارات معنى.

الأمر نفسه صحيح بالنسبة إلى output devices. قد يحمل monitor أو speaker أو haptic motor أو output device آخر بيانات قابلة للإدراك، لكن الجهاز لا يكمل التجربة. تكتمل التجربة عندما يدرك المستخدم النتيجة. شاشة مليئة بـ pixels مصيّرة بإتقان لا تزال ليست واجهة ناجحة إذا لم يستطع المستخدم رؤية ما قُدم أو فهمه أو الوصول إليه أو سماعه أو الشعور به أو التصرف تجاهه.

### العلاقة مع Systems

يقع Human Interface مباشرة تحت **Layer 1: Systems**. توفر طبقة System آخر معالجة صريحة لـ output في جانب الحاسوب وأول معالجة صريحة لـ interaction في جانب الحاسوب. يقع Human Interface وراء تلك الطبقة كمستلم output من system ومصدر فعل المستخدم.

تحدد هذه العلاقة الحافة السفلى لـ Stack. في التدفق من الأعلى إلى الأسفل، يسلّم system ‏output نحو المستخدم. وفي التدفق من الأسفل إلى الأعلى، يتلقى system أثر فعل المستخدم. لذلك system هو الطبقة الصريحة الأخيرة للعملية الآلية، بينما Human Interface هو الحد الضمني حيث تلتقي العملية الآلية بالتجربة الإنسانية.

بفصل هاتين الطبقتين، يتجنب النموذج الخلط بين سلوك الجهاز وتجربة المستخدم. قد يعرف system أن مفتاحًا ضُغط، أو أن مؤشرًا تحرك، أو أن صوتًا شُغّل. لكنه لا يعرف تلقائيًا ما فهمه المستخدم أو قصده أو شعر به أو لاحظه. تنتمي هذه الحقائق الإنسانية إلى ما وراء Stack الصريح، حتى وإن كان Stack موجودًا لخدمتها.

### إمكانية الوصول والتنوع الإنساني

يذكّر Human Interface النموذج أيضًا بأن المستخدمين ليسوا آلات قابلة للاستبدال. يدرك الناس ويتصرفون عبر قدرات وحواس وسياقات وأدوات وقيود وتفضيلات وبيئات مختلفة. قد يعتمد مستخدم أساسًا على visual output. وقد يعتمد آخر على auditory output أو tactile feedback أو keyboard navigation أو screen readers أو captions أو simplified motion أو alternate input devices أو أشكال وصول أخرى.

هذا لا يغير بنية Stack. بل يوضح لماذا يهم Stack. بفصل الطبقات، يستطيع CatalystUI تحديد موضع الفشل بشكل أفضل عندما يُسلّم output لكنه لا يكون قابلًا للإدراك بصورة ذات معنى، أو عندما يمتلك المستخدم قصدًا لكن لا يملك مسارًا قابلًا للاستخدام للتعبير عنه. يحافظ حد Human Interface على غرض التدفق كله مرئيًا: system لا ينتج output فقط؛ إنه يتواصل مع شخص.

قد يكون ذلك الشخص متعبًا أو مشتتًا أو لامعًا أو مرتبكًا أو ذا إعاقة أو في طور التعلم أو ينجز عدة مهام أو يحاول إنهاء شيء قبل الموعد النهائي بخمس دقائق. ما تزال الواجهة بحاجة إلى مقابلته كإنسان. ويفضل أن يكون ذلك من دون مطالبته أولًا بقراءة رسالة خطأ من أربعين صفحة.

### لماذا تهمّ الطبقة

يمنع Human Interface ‏Stack من الانتهاء عند الآلة. من دون هذه الطبقة الضمنية، سيتوقف النموذج عند system output وsystem input، كأن غرض الواجهة مجرد تحريك إشارات عبر hardware. سيفوّت ذلك الفكرة الأساسية. غرض Stack ليس إنتاج output فقط؛ بل جعل التواصل ممكنًا بين نظام معلومات ومستخدم.

بفصل Human Interface عن Systems، يحافظ النموذج على حد نهائي نظيف. تسلّم Systems ‏output وتستقبل input. ويدرك Human Interface ‏output وينتج action. يصف Stack الصريح العملية في جانب الآلة بين هذين الاتجاهين، بينما يذكرنا Human Interface الضمني بمن وُجدت العملية من أجله.

لهذا ينتمي Human Interface إلى Stack حتى لو لم يكن مرقمًا. المستخدم ليس طبقة تُنفذ أو تُصيّر أو تُحلل أو تُختبر بـ unit tests. المستخدم هو سبب وجود الطبقات. وبافتراض أن المستخدم إنسان، يعمل النموذج بجمال.
