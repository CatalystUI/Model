# 5.2 The Stack :: Digital Data

## 詳細な解説

### 最初の明示的レイヤー

**Digital Data** は Stack の最初の明示的レイヤーです。これは、内容、状態、またはリソースがコンピューターで読める形でアクティブなインターフェイスの流れに入った後、しかし Model が Structure & Semantics を適用したり、それを components、layout、rendering、presentation に変えたりする前のものを表します。保持された利用可能性が、Stack が直接扱い始められるものになる地点です。

このレイヤーが明示的なのは、Model がそのリソースをインターフェイスのプロセスの一部として説明できるようになるからです。Data Storage が、何かがアクティブな流れの外でどこに永続できるかを説明するのに対して、Digital Data は、読まれ、受け取られ、読み込まれ、ストリームされ、生成され、または別の形で Stack に利用可能になったアクティブな表現を説明します。それはもはやどこかで利用可能なだけではありません。今はシステムが処理できる形で存在しています。

### コンピューターで読める表現

Digital Data は、二進数として表現され、機械によって処理できる能力によって定義されます。このレイヤーでは、リソースは bytes、エンコードされたテキスト、受け取られたレスポンス、メモリ buffer、stream、または別の機械可読表現として保持されるかもしれません。正確な入れ物よりも、それが果たす役割のほうが重要です。それは解釈の前にある、リソースのアクティブな形です。

つまり、Digital Data を意味、構造、提示と混同してはいけません。bytes の列は文書、画像、コマンド、設定、音声ファイルを含むかもしれませんが、Layer 7 はその列がどのように理解されるべきかをまだ説明しません。内容が Stack 内にあり、システムがアクセスして次のレイヤーへ渡せる形で存在することだけを確立します。

### Structure and Semantics の前

Digital Data は **Layer 6: Structure & Semantics** のすぐ上にあります。Structure & Semantics が解釈する材料を表すからです。その解釈が起こるまで、Stack はその表現に含まれる規則、関係、フィールド、セクション、意味をまだ識別していません。リソースはすでに形式に従っているかもしれませんが、Model はまだその形式を適用していません。

保存された文書はすでにその形式に従って妥当かもしれず、ファイルはすでに整理された内容を含んでいるかもしれません。それでも Layer 7 は、その整理を理解済みの structure としてモデル化しません。Stack がその表現をどのように読むべきかの規則を適用し始めた瞬間、流れは Structure & Semantics へ移動しています。したがって Digital Data は無意味なのではありません。Stack の内部でまだ解釈されていないだけです。

### 上側の折り返し点

Digital Data は明示的な Stack の上側の折り返し点として働きます。上から下への流れでは、Stack がコンピューターで読める表現を、最終的にユーザーが知覚または相互作用できるものへ変換し始める場所です。流れはアクティブな表現から始まり、解釈、component 形成、整理、rendering、windowing、system delivery を通って下へ移動します。

下から上への流れでは、Digital Data は相互作用の結果が再び機械可読になる場所です。ユーザーの行動はルーティングされ、処理され、インターフェイス内の変更へ変換されるかもしれません。その変更は Stack を上へ移動し、Digital Data になることがあります。つまり、保持、送信、比較、再生成、または Data Storage へ戻すことのできるアクティブな表現です。このように Layer 7 は、インターフェイスサイクルの両方向に参加します。

### Digital Data と Domains

Digital Data はしばしば **Symbolic** domain と密接に関係します。通常、特定の感覚形式が選ばれる前に存在するからです。たとえばテキストファイルは後で視覚的に表示されるかもしれませんし、音声で読み上げられるかもしれませんし、別の形式へ変換されるかもしれませんし、直接提示されずに処理されるだけかもしれません。Layer 7 で重要なのは、ユーザーが最終的にそれをどう知覚するかではなく、その表現が Stack による解釈のために利用可能であることです。

これは Digital Data が symbolic だけであり得るという意味ではありません。リソースは、そのエンコードされた形の中に visual、auditory、tactile、multisensory な内容を含むことがあります。しかしこのレイヤー自体は、アクティブな Stack がそれを知覚可能または相互作用可能な結果へ変換する前の、コンピューターで読める表現を説明します。Domains は扱われている情報の種類を識別し、Stack はその情報が流れのどこにあるかを識別します。

### なぜこのレイヤーが重要なのか

Digital Data は、Model がインターフェイス作業の最初のアクティブなステップを飛ばすことを防ぎます。このレイヤーがなければ、Stack は保存から解釈へ直接移動し、保存されたリソースがアクセスされた瞬間に自動的に利用可能な structure を持つかのように扱ってしまいます。実際のシステムではそうではありません。何かはまず、解析、検証、整理、適応、レンダリング、提示の前に、アクティブな機械可読形式として存在しなければなりません。

Digital Data を Data Storage と Structure & Semantics の両方から分離することで、Model は三つの重要な区別を保ちます。Data Storage はアクティブな流れの外にある永続性を説明します。Digital Data は流れの中にあるアクティブなコンピューター可読表現を説明します。Structure & Semantics はその表現の解釈を説明します。これらの責任を分けておくことで、同じ保存リソースが複数の方法で読まれ、解釈され、変換され、提示され得る場合でも、Stack はインターフェイスの振る舞いをより正確に説明できます。
