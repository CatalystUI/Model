# 5.1 The Stack :: Data Storage

## 詳細な解説

### 暗黙の境界

**Data Storage** は Stack の暗黙的な上側の境界です。これは、明示的なレイヤーが扱い始める前に、内容、状態、またはリソースが利用可能なままである条件を表し、さらに相互作用の結果が後で保持される場所も表します。Model がこの境界を必要とするのは、インターフェイスが自分の対象をすべて無から作り出すわけではないからです。何かを解釈し、変換し、レンダリングし、またはそれに対して行動する前に、読めるもの、取得できるもの、受け取れるもの、参照できるものが必要です。

Data Storage が暗黙的なのは、Stack が保存そのものの内部機構をモデル化しないからです。Model は保存されたリソースに依存することがありますが、そのリソースがどのように保持されているかを細部まで説明する必要はありません。その関心は周囲の情報システムに属します。Stack は、何らかの内容がアクティブなインターフェイスの流れの一部になったところから始まります。

### 保存された利用可能性とアクティブな表現

Data Storage と Layer 7: **Digital Data** の違いは、**保存された利用可能性** と **アクティブな表現** の違いです。Data Storage は、何かが永続できる場所または条件を説明します。Digital Data は、そのものがコンピューターで読める表現としてモデル化されたプロセスに入った後の、最初の明示的な形を説明します。

たとえば、文書はファイルシステムに存在するかもしれません。レコードはデータベースに存在するかもしれません。レスポンスは API の向こうで待っているかもしれません。それがアクセス可能なだけの状態にある間は、Data Storage に属します。インターフェイスがその文書を読み、そのレコードを受け取り、そのレスポンスを開き、または別の形でリソースをアクティブな流れに持ち込むと、それは Layer 7 になります。重要な変化は、内容が突然意味を持つようになったことではありません。重要な変化は、それが Stack の内部で表現されるようになったことです。

### 永続性と変換

Data Storage は永続性と利用可能性に関わります。明示的な Stack は変換に関わります。保存されたリソースが Digital Data になると、Model はそれに何が起きるかを説明し始められます。Structure & Semantics によってどのように解釈され、Components, Controls, & Layouts に形づくられ、Graphs & Frames を通じて整理され、Renderer によって準備され、Window を通じて届けられ、System によって Human Interface へ運ばれるかです。

この分離が重要なのは、保存と変換が異なる問いに答えるからです。Data Storage は、何かが時間を越えて利用可能でいられるかを問います。Digital Data は、インターフェイスが現在どのようなアクティブな二進、テキスト、ストリーム、または受信された表現を扱っているかを問います。前者は保持を説明します。後者はモデル化された流れを開始します。

### 起点と戻り先の境界

上から下への流れでは、Data Storage は起点の境界として機能します。保存されたリソースが選択または取得され、Digital Data として Stack に入ります。その時点から、Model はそのリソースがどのように理解され、配置され、変換され、ユーザーへ届けられるかを追跡できます。Data Storage 自体はリソースをレンダリングせず、解析せず、レイアウトせず、解釈もしません。アクティブな表現が始まるための条件だけを提供します。

下から上への流れでは、Data Storage は戻り先の境界として機能します。ユーザーの相互作用は、インターフェイスの流れの中にある何かを要求、作成、更新、削除、または別の形で影響することがあります。その結果として生じた変更は Stack を上へ通り、再び Digital Data になることがあります。その結果が即時のプロセスを越えて利用可能である必要があるなら、保持された状態として Data Storage に戻ります。Stack は、結果が永続性へ戻ったことを認識するために、すべての書き込み戦略、データベーストランザクション、キャッシュ更新、ネットワーク同期ステップをモデル化する必要はありません。

### 文脈内の例

そのため、Data Storage は多くの技術を通じて現れますが、そのどれか一つによって定義されるわけではありません。ファイルシステム、MySQL データベース、MongoDB collection、API-backed service、クラウドオブジェクトストア、デバイスのメモリ領域、ストリーミングサービスは、アクティブな Stack の外で保持された利用可能性を提供する場合、すべて Data Storage として機能できます。特定のファイル、レコード、レスポンス、buffer、stream がインターフェイスの流れに持ち込まれると、Model はそのアクティブな表現を Digital Data として扱います。

### なぜ分離が重要なのか

Data Storage を Layer 7 から分離することで、Stack は明確さを保ちます。この区別がなければ、Model は何かが保持されている場所と、インターフェイスがそれを扱い始めたときの形を混同してしまいます。それにより Digital Data は永続性とアクティブな表現の両方を担当することになり、明示的なレイヤーの目的が弱まります。

Data Storage を暗黙的なままにすることで、Model は明確な境界を保ちます。保存はインターフェイスの流れを取り囲み、Digital Data はその流れを始めます。これにより Stack は、背後にあるあらゆる保存機構に絡め取られることなく、特定のアクティブな表現の変換を説明できます。Data Storage は保持された内容がどこから来るか、保存された結果がどこへ戻るかを説明します。Layer 7 は、その内容をインターフェイスが理解し、変換し、最終的に提示できるものへ変える明示的なプロセスを開始します。
