# 5.9 The Stack :: Human Interface

## 詳細な解説

### 暗黙の人間側の境界

**Human Interface** は Stack の暗黙的な下側の境界です。これはユーザーを表します。System から知覚可能な output を受け取り、interaction input になり得る行動を生み出す人です。もっと簡単に言うと、このレイヤーはあなたです。

当たり前に聞こえるかもしれませんが、重要です。Stack は、ユーザーと情報システムの間のコミュニケーションプロセスを説明するために存在します。Data Storage が、保持された内容がアクティブな流れへ入ったり出たりする境界を説明するなら、Human Interface は反対側の境界を説明します。コンピューターの output が最終的に人間の体験の一部になり、人間の行動が system へ戻る経路を始める場所です。

Human Interface が暗黙的なのは、Model がユーザーの身体、心、注意、感情、感覚、意図、記憶、選択を直接表さないからです。CatalystUI は system が output をユーザーへ届ける方法や、ユーザーの行動が interaction input になる方法を説明できます。しかし人間全体をモデル化するふりはしません。それは少し野心的です。あと、かなり怖いです。Stack は強力ですが、renderer 付きの心理学教科書になる必要はありません。

### 知覚可能な Output の受け手

上から下への流れでは、Human Interface は知覚可能な output の受け手です。Digital Data は明示的な Stack を通り、解釈され、形づくられ、整理され、レンダリングされ、window を通じて届けられ、system によって運ばれ、最終的に知覚可能になります。その output がユーザーの感覚に届いたとき、明示的な Stack は下向きの経路を完了しています。

これは、ユーザーが Digital Data を直接受け取るという意味ではありません。人は自然に一とゼロ、memory buffers、draw calls、audio samples、system events を知覚するわけではありません。ユーザーが知覚するのは system の仕事の結果です。光、音、振動、動き、テキスト、空間的変化、または別の感覚 output です。Human Interface は、その output が単に届けられたものではなく、体験され始める場所です。

この区別は Model を正直に保ちます。System は output を提供できますが、理解を強制することはできません。ディスプレイはボタンを表示し、スピーカーは音を鳴らし、デバイスは振動できますが、ユーザーはなお人間としてその結果を知覚し解釈しなければなりません。Model はこの境界を認めながら、関わるすべての個人的、生物学的、文脈的要因を定義しようとはしません。言い換えると、CatalystUI は output を人間まで届けられます。通知を無視しないよう人間を説得することはできません。残念ながら。

### Interaction の源

下から上への流れでは、Human Interface は行動の源です。ユーザーは見て、聞いて、感じて、理解し、反応し、決めて、それから何かをします。その行動は、キーを押すこと、ポインターを動かすこと、画面に触れること、コマンドを話すこと、ノブを回すこと、センサーフィールドを歩くこと、または system が受け取れる別の振る舞いかもしれません。

行動そのものは明示的な Stack の外で始まります。Model は、ユーザーが行動に至った完全な内部プロセスを直接説明しません。System がその行動の効果を受け取った時点で、戻り経路のモデル化を始めます。その時点で行動は interaction input になり、Layer 1: Systems に入り、Stack を上へ渡されます。

これにより **human action** と **system interaction** の明確な区別が保たれます。Human action はユーザーがすることです。Interaction input は、その行動から system が受け取るものです。二つは密接に関係していますが、同一ではありません。人は何かをクリックするつもりで別のものを誤ってクリックすることがありますし、何かを取ろうとしてキーに触れてしまうこともあります。System はその両方を受け取るかもしれませんが、そのうち一つだけがユーザー意図の意味ある表現である可能性が高いです。偶発的な input が目的だった場合は別です。その場合、おめでとうございます。インターフェイスはかなり実験的な段階に入りました。

### なぜこのレイヤーが暗黙的なのか

Human Interface は Data Storage と同じ理由で暗黙的です。流れには必要ですが、明示的な変換レイヤーとして直接モデル化されないからです。Stack はユーザーに依存しますが、ユーザーを変換しません。ユーザーを parse しません。ユーザーを render しません。ユーザーを adapt しません。ユーザーを component として保存しません。たぶんそのほうがいいです。

代わりに、Model は Human Interface を system の下端を囲む生きた境界として扱います。明示的な Stack は output がどのように準備され届けられるかを説明でき、受け取られた interaction がどのように上へ移動するかを説明できます。しかし人間の体験そのものを所有すると主張する手前で止まります。

この境界が特に重要なのは、ユーザーが単なる別のデバイスではないからです。ディスプレイは visual output を提供します。キーボードは input signals を提供します。ユーザーは知覚し、解釈し、選び、応答し、誤解し、学び、ためらい、間違え、ときには自信満々に間違ったボタンをクリックします。Model はその違いを尊重すべきです。したがって Human Interface は、Stack が人間とのコミュニケーションのために作られているため存在します。しかし人間が機械側の変換プロセスの一部ではないため、暗黙的です。

### 知覚と意図

Human Interface は、知覚と意図を結びつけることでコミュニケーションサイクルを完了します。一方の方向では、system が知覚可能なものを提供します。もう一方では、ユーザーが行動で応答します。これが CatalystUI の中心にある会話的なループを作ります。System は output を通じて話し、ユーザーは interaction を通じて応答し、system はその応答を処理して交換を続けます。

だからこそ Human Interface は input devices に還元できません。Keyboard、mouse、touchscreen、microphone、camera、controller は interaction を捉える助けになるかもしれませんが、それらはユーザーではありません。それらは、ユーザーの行動が Stack へ入るための system-accessible な経路です。Human Interface は、その信号に意味を与える知覚と意図を持つ人です。

Output devices についても同じです。Monitor、speaker、haptic motor、または別の output device は知覚可能なデータを運ぶかもしれませんが、デバイスが体験を完了するわけではありません。体験はユーザーが結果を知覚したときに完了します。完璧にレンダリングされた pixels で画面が満たされていても、ユーザーが見られず、理解できず、届かず、聞けず、感じられず、行動できないなら、それは成功したインターフェイスではありません。

### Systems との関係

Human Interface は **Layer 1: Systems** のすぐ下にあります。System レイヤーは、output について最後の明示的なコンピューター側処理を提供し、interaction について最初の明示的なコンピューター側処理を提供します。Human Interface はそのレイヤーの先にあり、system output の受け手であり、ユーザー行動の源です。

この関係は Stack の下端を定義します。上から下への流れでは、system は output をユーザーへ届けます。下から上への流れでは、system はユーザー行動の効果を受け取ります。したがって system は機械操作の最後の明示的レイヤーであり、Human Interface は機械操作が人間の体験と出会う暗黙の境界です。

これらのレイヤーを分離することで、Model はデバイスの振る舞いとユーザー体験を混同しません。System はキーが押されたこと、ポインターが動いたこと、音が再生されたことを知るかもしれません。しかしユーザーが何を理解し、何を意図し、何を感じ、何に気づいたかを自動的に知るわけではありません。それらの人間的な現実は、Stack がそれらに奉仕するために存在していても、明示的な Stack の外にあります。

### アクセシビリティと人間の多様性

Human Interface は、ユーザーが交換可能な機械ではないことも Model に思い出させます。人は異なる能力、感覚、文脈、道具、制限、好み、環境を通じて知覚し行動します。あるユーザーは主に visual output に依存するかもしれません。別のユーザーは auditory output、tactile feedback、keyboard navigation、screen readers、captions、simplified motion、alternate input devices、または他のアクセス形態に依存するかもしれません。

これは Stack の構造を変えません。Stack がなぜ重要かを明確にします。レイヤーを分けることで、CatalystUI は output が届けられているのに意味ある形で知覚できないとき、またはユーザーに意図があるのにそれを表す利用可能な経路がないとき、どこで失敗が起きているかをよりよく識別できます。Human Interface の境界は、流れ全体の目的を見えるままにします。System は単に output を生成しているのではなく、人とコミュニケーションしているのです。

その人は疲れているかもしれません。気が散っているかもしれません。優秀かもしれません。混乱しているかもしれません。障害があるかもしれません。学習中かもしれません。複数のことを同時にしているかもしれません。締め切りの五分前に何かを終わらせようとしているかもしれません。それでもインターフェイスは、その人を人間として迎えなければなりません。できれば、先に四十ページのエラーメッセージを読ませずに。

### なぜこのレイヤーが重要なのか

Human Interface は、Stack が機械で終わってしまうことを防ぎます。この暗黙のレイヤーがなければ、Model は system output と system input で止まり、インターフェイスの目的が単にハードウェアを通じて信号を動かすことだと扱ってしまいます。それでは要点を外します。Stack の目的は output を生成することだけではありません。情報システムとユーザーの間のコミュニケーションを可能にすることです。

Human Interface を Systems から分離することで、Model は明確な最後の境界を保ちます。Systems は output を届け、input を受け取ります。Human Interface は output を知覚し、action を生みます。明示的な Stack はその二つの方向の間にある機械側のプロセスを説明し、暗黙の Human Interface はそのプロセスが誰のためにあるのかを思い出させます。

だからこそ Human Interface は、番号が付けられていなくても Stack に属します。ユーザーは実装され、render され、parse され、unit-test されるレイヤーではありません。ユーザーはレイヤーが存在する理由です。そして、ユーザーが人間であると仮定するなら、Model は見事に機能します。
