# 4. Domains

## 高レベル概要

CatalystUI Model を説明するには、まず domains から始める必要があります。_domain_ は、相互作用中に扱われるデータのカテゴリを表します。これは情報の流れを分解する最初のステップです。システムがどの_種類_の情報を扱っているかを識別します。店舗のドアセンサーは、動きを検出するために視覚的または空間的な手がかりを使うかもしれません。ゲームコントローラーは、触覚情報を使ってハプティックフィードバックを生成するかもしれません。スマートスピーカーは、音声を処理するときに聴覚情報を扱うかもしれません。ほとんどの場合、domains は人が世界を感じ取る方法と一致します。Model はまた、データが特定の感覚に到達する前の状態や、複数の感覚に同時にまたがるデータも考慮します。その結果、七つの domains は “symbolic”、“visual”、“auditory”、“tactile”、“olfactory”、“gustatory”、“multisensory” として定義されます。

Domains は有用です。なぜなら、情報の流れを認識し、診断し、ユーザーの必要に合わせて形作りやすくするからです。情報がどの domain に属するかを識別することで、システムが何をしているのか、何をしていないのか、そしてユーザー体験のどの部分が欠けている可能性があるのかをより明確に見ることができます。これはアクセシビリティにおいて特に重要です。インターフェイスが視覚だけで伝える場合、Model は、触覚、聴覚、または他の情報形態も考慮する必要があるかもしれないことを認識させてくれます。Domains は情報がユーザー体験にどのように参加するかを説明するため、データを domain に分類するには、まずそれが相互作用でどの役割を果たすのかを問う必要があります。見られることを意図したデータは visual、聞かれることを意図したデータは auditory、感じられることを意図したデータは tactile です。テキストファイルのように、まだ特定の感覚に割り当てられていないデータは symbolic です。映像、音、コントローラーの振動を組み合わせたビデオゲームのように、複数の感覚カテゴリが一つの体験として連携する場合、それは multisensory です。

## Model における Domains の役割

データが domain に分類されると、相互作用にはより明確な出発点が生まれます。システムがどの情報を扱うのか、ユーザーがどのような体験を持つのか、そして他のコミュニケーション形態を考慮する必要があるのかが分かります。そのカテゴリが確立されると、Model はデータの種類を識別する段階から、データがインターフェイス自体をどのように移動するのかを説明する段階へ進むことができます。
