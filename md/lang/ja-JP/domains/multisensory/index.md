# 4.7 Domains :: Multisensory

## 詳細な解説

**multisensory** domain は、統一された体験の一部として、複数の感覚のために形づくられたデータを表します。これは、同じシステムに複数の出力が存在するだけのことではありません。異なる感覚形式が結合され、調整され、ルーティングされ、または一緒に届けられ、ユーザーがそれらを「*一つのもの*」として受け取る地点です。

この区別は重要です。システムは複数種類の出力を含んでいても、意味のある multisensory になっていないことがあるからです。プログラムがある場所で画像を見せ、別の場所で音を鳴らしても、それらの出力が無関係なら、別々のコミュニケーション形式のままです。multisensory data は、それらの形式が意図的に結びつけられたり、同時に提示されたりするときに現れます。同期された音声を持つ動画、衝突音と物理的フィードバックを組み合わせるゲームイベント、または表示経路とスピーカー経路を分けて協調した出力を送るデバイスは、いずれもこの domain に属することがあります。体験が出力間の関係に依存するからです。

multisensory data は、情報が孤立した一つの表現としてではなく、調整された配送として扱われる地点の近くに現れることがよくあります。データはストリームへ統合されたり、複数の出力へ分けられたり、複数のデバイスのために同時に準備されたりします。重要なのは、すべてが一つのケーブル、ファイル、オブジェクトを通ることではありません。重要なのは、ユーザーが結果を一つの意味ある出来事として受け取ることです。

### multisensory data を理解する

multisensory data を理解するうえで有用な方法は、**構成**、**同期**、**ルーティング**を考えることです。

**構成** は、異なる出力形式がどのようにまとめられるかを表します。ビデオ通話では、話し声、顔の動き、字幕、インターフェイスのフィードバックがすべて同じ体験に貢献するかもしれません。これらの要素は互いを完全には置き換えません。一つのコミュニケーション全体へ構成されることで、その意味はより強くなります。

**同期** は、それらの出力が時間の中でどのように関連し続けるかを表します。遅れて届く音、出来事が過ぎてから発生する振動、発話に遅れる字幕は、個々の出力がまだ機能していても、体験を壊れたもののように感じさせることがあります。multisensory data はタイミングに依存します。信号同士の関係が意味の一部であることが多いからです。

**ルーティング** は、統一された体験が分かれた経路を通じてどのように届けられるかを表します。システムは出力の一部をディスプレイへ、別の一部をスピーカーへ、さらに別の一部をハプティックデバイスへ送るかもしれません。それらの経路は物理的には分かれていても、正しく調整されていれば、ユーザーはそれらを一つのインタラクションとして理解します。multisensory data は、配送では分割されながらも意味では統一されたままである必要が多いため、ルーティングは重要です。

### multisensory な意味

multisensory output は関係を通じて意味を表現します。音はユーザーが見ているものを確認するかもしれません。振動はユーザーが聞いているものに重みを与えるかもしれません。字幕は、話し声の中で失われるかもしれない情報を保持するかもしれません。それぞれの部分には固有の感覚形式がありますが、より大きな意味は、それらの部分がどう一緒に働くかから生まれます。

これにより、multisensory design は単に効果を追加することとは異なります。ボタンに音を加えても、それだけで意味が生まれるわけではありません。アラートに振動を加えても、それだけで役立つわけではありません。視覚アニメーションと音声が同じ出来事を伝えているなら、インタラクションを強めることができますが、異なることを示唆すれば混乱を生むこともあります。この domain が有用なのは、出力が協力しているのか、それとも単に共存しているのかを問いかけるからです。

multisensory data は、単一の感覚経路よりも粘り強く意味を運べることもあります。一つの出力が見逃されても、別の出力がメッセージの一部を保持できるかもしれません。ユーザーが視覚に頼れない場合、音が重要な情報を運ぶかもしれません。環境が騒がしい場合、触覚や見える構造が代わりにそれを運ぶかもしれません。よく設計された multisensory experience は、意味を無作為に散らしません。目的を持って分配します。

### multisensory data とアクセシビリティ

multisensory domain はアクセシビリティにおいて特に重要です。意味が異なる知覚形式をまたいで保持されているかを見つける助けになるからです。複数の出力がうまく調整されていれば、ユーザーは何が起きたかを理解する方法を複数持てます。調整が悪い場合、システムは表面上アクセシブルに見えても、重要な意味を一つの感覚経路に閉じ込めたままにすることがあります。

視覚的に現れ、音として鳴り、物理的フィードバックも提供する通知は、同じ出来事を複数の方法で伝えられます。これは役立つことがありますが、それぞれの形式が意味を持ち、適切である場合に限られます。音が視覚出力にはない情報を運んでいたり、視覚出力が他の出力ではアクセスできない詳細を含んでいたりするなら、体験はまだ不均等かもしれません。multisensory design は効果を複製するだけではなく、意図を保持すべきです。

ここではシステムがユーザーの制御も尊重しなければなりません。あるユーザーは一つの感覚を通じてより多くの出力を必要とし、別の感覚からは少なくしたいかもしれません。別のユーザーは音を無効にしたり、動きを減らしたり、振動を避けたり、字幕に頼ったりするかもしれません。multisensory experience は、体験を最初に一貫したものにしていた意味を失わずに適応できるとき、最も強くなります。

multisensory data は、情報が複数のチャネルを通じて同時に届けられる必要があるシステムによく現れます。メディア再生は、動く映像と音を一つのストリームへ組み合わせるかもしれません。シミュレーターは、現実世界の出来事を表すために、視覚、音声、物理的フィードバックを調整するかもしれません。オペレーティング環境は、異なる種類の出力を異なるデバイスへルーティングしながら、ユーザーには一つの統一されたインタラクションを提示するかもしれません。

これらの例は、multisensory data を分離した domains のゆるい集まりとして扱えない理由を示しています。出力が同期され、構成され、または一緒にルーティングされると、それらの関係自体が情報の一部になります。システムはもはや「何が見られるべきか？」や「何が聞かれるべきか？」だけを問うているのではありません。ユーザーが一つの出来事を理解するために、複数の知覚形式がどう一緒に働くべきかを問うています。

これは、multisensory data をうまく設計することがしばしば難しい理由も説明します。各出力にはそれぞれの限界、タイミング、配送方法、ユーザーの期待があります。それらを組み合わせるには、同じメッセージをあらゆる場所へ送る以上のことが必要です。意味のどの部分がどの形式に属するのか、それらの形式がどう接続されたままでいるのか、そしてその一つが利用できない場合に何が起こるべきかを決める必要があります。
