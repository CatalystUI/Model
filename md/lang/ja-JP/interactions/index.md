# 7. Interactions

## 高レベル概要

ここまで来ると、CatalystUI Model を通じて、ユーザーインターフェイスを以前よりはるかに明確に説明できます。情報の流れを識別し、その情報を domains に分類し、Stack を通して追跡し、connectors がそれを一つのレイヤーから次のレイヤーへどのように移動し変換するかを説明できます。そうすることで、ユーザーインターフェイスの背後にある謎の多くが解け始めます。情報がどこから始まり、どこへ行き、どのように変化し、最終的にどのようにユーザーに届くのかを見ることができます。

では、これで終わりでしょうか。まだです。まだ十分に扱っていない重要なパズルの一部があります。_あなた_です！

どんなユーザーインターフェイスでも、最も重要な部分はそれを使う人です。ユーザーがいなければ、インターフェイスは目的を失います。その時点では、サーバーが API にデータを送る、あるプログラムが別のプログラムへ命令を渡す、というように、機械が別の機械と通信しているだけを説明していることになります。そのような交換は有用かもしれませんが、Model の全体の主題ではありません。ユーザーインターフェイスは、人が何かを知覚し、理解し、選択し、または何らかの形で応答する必要があるために存在します。たとえあなたの猫がキーボードに乗り、猫の神々を呼び出し、地球を彼らの正当な玉座へ返したとしても、要点は同じです。システムの外にある何かがシステムに作用し、インターフェイスはそれに応答しなければなりません。

これが “Human Interface” が重要な理由です。私たちはすでにそれを Stack の下部にある暗黙の終点として識別しましたが、そこで何が起こるのかをより詳しく見る必要があります。情報はユーザーに届いて終わるわけではありません。ユーザーは応答できます。クリックし、話し、動き、入力し、聞き、無視し、ためらい、誤解し、またはシステムが予期しない方法で行動できます。その応答は流れの一部になります。

そのため、もう一つ識別して追跡すべきデータがあります。_interaction_ です。interaction とは、情報がユーザーに届き、ユーザーが応答し、システムがその応答を継続する流れの一部として受け取るときに起こる交換です。それは、Model が単なる提示についてのものではなく、参加についてのものになる地点です。インターフェイスは、もはや人に情報を見せるだけではありません。その人が次に起こることへ影響を与えられるようにしています。

より直接的に言えば、_interaction とは行動の背後にある意図_です。クリック、タップ、スワイプ、コマンド、動き、話された言葉は、その見える部分にすぎません。その行動の背後には、ユーザーが_しようとしている_ことがあります。メニューを開きたい、前に進みたい、フォームを送信したい、曲を一時停止したい、警告を閉じたい、明かりをつけたい、または単に何が起きているのか知りたいのです。システムは信号だけを受け取るかもしれませんが、ユーザーは単に信号を送っているのではありません。ユーザーは要求をしています。

### 現代技術への不満

現代の技術に対する多くの不満はここから始まります。ユーザーはある意図を持って行動しますが、システムがその意図を誤って解釈したり、遅すぎる応答を返したり、完全に無視したりします。私たちは皆これを経験しています。クリックできそうに見えるのに何もしないボタン、固まっているように見えるページ、こちらの声を聞いたのに理解しなかったデバイス、技術的には動作したのに私たちが知覚できる形で応答しなかったインターフェイス。どの場合も、ユーザーは要求をしましたが、システムは明確に答えませんでした。そのとき、不満は謎ではありません。それは、interaction が誤解され、遅延し、または未解決のまま残された自然な結果です。

これが interactions が特別な理由です。他の多くのデータ形式とは異なり、それらは双方向であり、変換的でもあります。システムからユーザーへ移動し、ユーザーから再びシステムへ戻ります。移動するにつれて変化します。output として始まったものが perception になり、perception が intent になり、intent が action になり、その action が input になることがあります。そしてシステムは応答し、サイクルが再び始まります。これは interaction を、保存されたファイル、レンダリングされた画像、一つの音とは異なるものにします。interaction は単にどこかへ運ばれるデータではありません。選択によって形作られるデータです。

その意味で、interactions は深く人間的なものを示しています。私たちは情報を受動的に受け取る機械ではありません。気づき、考え、選び、ためらい、誤解し、自分を修正し、もう一度試し、時には同じボタンを十七回押します。_今度こそ_動くはずだと思うからです。interaction が存在するのは、人に agency があるからです。それはユーザーが選ぶ能力と、システムがその選択を受け取り応答する能力によって定義されます。選択がなければ、本当の interaction はありません。あるのは output だけです。

もちろん、機械も交換を形作ることができます。多くの場合、interaction はシステムがユーザーへ何かを提示するところから始まります。画面、音、プロンプト、警告、振動、出入口、その他の信号です。システムは、入力を拒否したり、window を閉じたり、タイムアウトしたり、要求を無視したりすることで交換を止めることもできます。しかしその場合でも、interaction が本当に消えたわけではありません。システムが応答しなければ、ユーザーは待ち、再試行し、混乱し、いら立ち、立ち去り、デバイスを再起動し、またはそのプログラムを二度と使わないと決めるかもしれません。動きの言葉をゆるく借りるなら、システムが継続を拒んだからといって、行動がただ消えるわけではありません。ユーザーはなお動きます。体験はなお変化します。流れはなお重要です。

だからこそ、ユーザーインターフェイスは、コンピューターが宇宙の中心であるかのように設計されてはなりません。そうではありません。コンピューターは人間の目的に仕えるために存在します。私たちが創造し、学び、整理し、コミュニケーションし、礼拝し、構築し、想像し、そうでなければ届かない問題を解くのを助けます。インターフェイスがユーザーを忘れると、それは冷たく、いら立たしく、不必要に難しいものになります。しかしユーザーの意図を尊重し、明確に応答し、情報を正しい経路で運ぶとき、技術は壁ではなく道具のように感じ始めます。

これが CatalystUI Model の核心です。保存されている情報、それが属する domains、それが通るレイヤー、それを変換する connectors、そして交換を始めた人へ戻す interaction まで、旅全体を見る方法を与えてくれます。ユーザーインターフェイスを、ばらばらの widgets、windows、APIs、renderers、devices の山として扱うのをやめ、_人_と_機械_の間の完全なコミュニケーションシステムとして認識できるようにしてくれます。

### すべての背後にある目的

何年もの間、夢は単純でありながら頑固でした。技術は、これほど壊れているように感じる必要はないはずだ、ということです。機械と明確に相互作用する方法を与えるだけのために、プログラムが肥大化し、壊れやすく、プラットフォームに縛られる必要はありません。framework が単純な考えを混乱の層の背後に隠す必要はありません。ユーザーインターフェイスが、人にコンピューターのように考えることを強制する必要はありません。コンピューターは人を理解するように設計されることが重要です。CatalystUI が存在するのは、その夢が不可能ではないからです。ただ、本当に起きていることを説明できるだけの明確なモデルが必要だったのです。

Stack は構造を与えます。Domains は扱っている情報の種類を教えてくれます。Connectors はその情報がどのように移動し変化するかを説明します。Interactions は、そもそもなぜそれが重要なのかを思い出させます。これらは一緒になって、コンピューターをもう一度人を中心に設計する方法を形作ります。流行を中心にするのではなく、framework の恣意的な決定を中心にするのでもなく、受け入れろと_言われた_制限を中心にするのでもなく、人間とそのシステムの間にある_実際の情報の流れ_を中心にするのです。

だから CatalystUI Model は重要なのです。だからこそ、何年もの作業、愛、心、憎しみ、苛立ち、希望がそこへ注ぎ込まれました。そして、だからこそあなたがここにいてくれて嬉しいのです。Catalyst の宇宙へようこそ。私の冒険の一部にでも加わってくれたことを嬉しく思います。それがあなたの世界の見方を、少しでも良い方向へ形作ったことを願っています。
