# 2. 概要

ユーザーインターフェイスがどのように機能するかを理解するには、まず「_情報の流れ_」を定義する必要があります。人々は意識しているかどうかに関係なく、毎日、スマートフォン、コンピューター、店舗入口のドアセンサー（これについては後で説明します）などの情報システムと相互作用しています。各システムでは、情報が提示され、ユーザーがそれを解釈し、必要に応じて応答し、システムがその応答を処理します。その後、システムは再び情報を提示し、相互作用の間、このサイクルが繰り返されます。サイクルはどの地点からでも始まり得ます。情報は、ユーザーがそれを解釈できるずっと前に提示されていたかもしれませんし、情報が提示されていない状態でユーザーが応答することもあります。流れがいつ、どのように始まるかに関係なく、同じサイクルが適用されます。

CatalystUI Model は、この流れを中心に構築されています。これは、システムが従来のユーザーインターフェイスに見えない場合でも、ユーザーと情報システムの間で情報がどのように流れるかを説明するための高レベルな構造を提供します。言い換えると、店舗のドアセンサーは人をほとんど魔法のように「感知」しているように見えるかもしれませんが、情報の流れで見ると、その過程は単純です。ユーザーは出入口を見て、進む道を認識し、検知エリアに入ります。その移動がシステムへの入力になります。システムはそれを処理し、知覚可能な出力としてドアを開け、ユーザーはそこを通過することで応答します。短い遅延の後、システムはドアを閉じ、その交換は次の行動がサイクルを再開するまで終了します。

情報の流れと並行して、_ユーザーインターフェイス_は、その流れが特定の情報システム内でどのように起こるかを定義します。システムが入力を受け取り、出力を生成し、ユーザーがそれと相互作用できるようにする方法を決定します。各システムには異なる要件があるため、時間の経過とともに、これらの相互作用を記述し実装するさまざまな方法が発展してきました。その中には “human interfaces”（“HI”）、“human-machine interfaces”（“HMI”）、“human-computer interfaces”（“HCI”）などがあります。現代のコンピューター時代において、これらのインターフェイスの最も身近な形は “graphical user interface”（“GUI”）です。

異なる実装を比較すると、共通するパターンが見え始めます。外見上の違いにもかかわらず、すべてのユーザーインターフェイスに現れる三つの概念を識別できます。1）データを分類し整理する “domains”、2）データを表現し説明する “the stack”、3）データを変換、変更、翻訳する “connectors” です。各概念は単独でも有用ですが、合わせることで、インターフェイス全体と個々のプロセスの両方を説明できる_可逆的な_ _システム_になります。ここに CatalystUI Model の強さがあります。相互作用を分類、表現、翻訳に分けることで、情報システムを説明し、デバッグし、理解しやすくするのです。
