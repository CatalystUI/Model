# 6.6 Connectors :: Native

## Подробное обсуждение

### От Windows к Systems

Коннектор **Native** находится между **Layer 2: Windows** и **Layer 1: Systems**. Он соединяет window с лежащей под ней system, чтобы вывод мог быть доставлен, а взаимодействия могли быть приняты через фактическую среду, в которой работает программа.

Layer 2 даёт Stack window: ограниченное представление, контейнер или точку доставки. Layer 1 даёт Stack system: операционную среду, доступ к аппаратуре, сервисы, устройства и native behavior, которые делают window возможной. Коннектор Native является точкой перехода между ними.

Именно здесь Stack наиболее прямо касается практической реальности вычислений. Window не существует только в воображении. Что-то должно попросить system создать её, настроить, поддерживать, обновлять и сообщать через неё о взаимодействиях. Этим «чем-то» является коннектор Native.

### Определение Bindings

**binding** — это управляемое соединение между одним слоем и функциональностью, предоставленной другим. В коннекторе Native bindings раскрывают поведение system уровню window в форме, которую программа может использовать, не заставляя window становиться самой system.

Native binding может раскрывать возможность создать window, изменить её заголовок, получить ввод с клавиатуры, отреагировать на движение указателя, изменить размер активной области, запросить фокус, обратиться к устройству или связаться с системным сервисом. Детали зависят от system и реализации, но идея остаётся той же: binding даёт пригодное к использованию соединение с native functionality.

Bindings важны потому, что system может иметь мощные возможности, которые не становятся автоматически доступными языку или структуре, используемым остальной частью Stack. Коннектор Native собирает, формирует и использует эти соединения.

### Предоставление Native Access

Во многих реализациях коннектор Native в основном предоставляет bindings к низкоуровневой функциональности system. Это может казаться обычным, потому что разработчики знакомы с native APIs, platform libraries, вызовами операционной системы и интерфейсами устройств. Но в Stack это не случайные детали реализации, а средство, через которое Layer 2 получает доступ к Layer 1.

Графической window может понадобиться binding к platform windowing API. Интерфейсу командной строки может понадобиться binding к вводу и выводу терминала. Специализированному устройству могут понадобиться bindings к кнопкам, датчикам, динамикам, световым индикаторам или другим устройствам, которыми управляет system.

Важна не конкретная платформа, а то, что window не может доставлять вывод или принимать взаимодействие без способа общаться с system, которая её содержит.

### Больше, чем Wrapper

Коннектор Native легко назвать wrapper вокруг system APIs, потому что он часто раскрывает native behavior. Но wrapper описывает стиль реализации, а binding описывает то, что коннектор на самом деле предоставляет.

Native — не просто набор platform calls под window. Это формальное отношение между window и system. Он определяет, как window получает существование, поддержанное system, как поведение system становится доступным Stack и как взаимодействия, возникшие в system, начинают двигаться вверх.

Модель не пытается только повторить исторические термины разработчиков. Она описывает сам процесс: коннектор Native важен потому, что связывает Layer 2 с Layer 1.

### Создание и поддержание Window

В нисходящем потоке коннектор Native позволяет window работать через system. Window может потребоваться создать, показать, скрыть, изменить размер, переместить, сфокусировать, обновить или закрыть. Эти действия требуют отношения с system, потому что именно system предоставляет среду, в которой они могут происходить.

Коннектор Native раскрывает bindings, нужные для этих действий. Через него Layer 2 может запросить поведение system, не забирая на себя всю ответственность за управление system. Window остаётся ограниченной точкой доставки; system остаётся средой, предоставляющей нижележащую функциональность.

Это важно, потому что systems различаются. Разные операционные системы, устройства, runtimes и среды предоставляют разные APIs и поведение. Коннектор Native даёт Stack место для представления этих различий, не заставляя остальную Модель становиться зависящей от конкретной system.

### Получение Interactions

Поскольку Stack обратим, коннектор Native является первым явным коннектором, участвующим в момент, когда взаимодействие входит из system.

Нажатие клавиши, движение указателя, касание, действие контроллера, сигнал устройства, изменение размера, изменение фокуса или другое событие, возникшее в system, должно перейти из Layer 1 в Layer 2. Коннектор Native принимает или раскрывает сведения о системном взаимодействии и переносит их в window.

Оттуда взаимодействие может продолжить движение вверх через Surface в Renderers, затем через Bridge, Adapter, Parser и Data по мере необходимости. Коннектор Native обычно не решает, что означает взаимодействие. Он связывает источник взаимодействия в system с путём взаимодействия в window.

Так нижняя граница остаётся чистой: system не обязана понимать верхние слои, а верхние слои не должны вести себя так, будто они сами являются system.

### Сохранение Boundary

Коннектор Native должен сохранять границу между window и system. Он раскрывает нужную функциональность system, но не стирает различие между двумя слоями.

Binding даёт доступ без тождества. Window может использовать функциональность system, не становясь system. System может предоставлять поведение, не становясь window. Коннектор определяет отношение между ними.

Эта граница позволяет CatalystUI описывать window последовательно в разных средах. Одна system может предоставить desktop window, другая — terminal, третья — канал вывода конкретного устройства, ещё одна — удалённую или виртуализированную среду. Native bindings различаются, но роль коннектора остаётся той же.

### Почему Connector важен

Коннектор Native не позволяет Stack путать window с system, которая её предоставляет. Без него Windows должен был бы напрямую содержать поведение, зависящее от system, или Systems должен был бы понимать более высокоуровневое понятие window.

Windows остаётся ответственным за ограниченный контекст, через который проходят вывод и взаимодействие. Systems остаётся ответственным за нижележащую среду, сервисы, устройства и native behavior. Коннектор Native отвечает за binding между ними.

Это последний явный коннектор Stack. Здесь моделируемый интерфейс достигает system под собой. Он может выглядеть как platform access и быть реализован через native libraries, вызовы операционной системы, device APIs или runtime services. Но его назначение проще: предоставить bindings.

Коннектор Native связывает window с system, позволяя выводу покинуть Stack, а взаимодействию войти в него. Так он завершает явный путь между моделируемым интерфейсом и реальной средой, в которой этот интерфейс должен жить.
