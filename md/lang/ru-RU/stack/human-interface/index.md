# 5.9 The Stack :: Human Interface

## Подробное обсуждение

### Подразумеваемая человеческая граница

**Human Interface** — это подразумеваемая нижняя граница Stack. Он представляет пользователя: человека, который получает воспринимаемый output от system и производит действия, которые могут стать interaction input. Проще говоря, этот слой — вы.

Это может звучать очевидно, но важно. Stack существует, чтобы описывать процесс коммуникации между пользователем и информационной системой. Если Data Storage объясняет границу, где удержанное содержимое может входить в активный поток или выходить из него, Human Interface объясняет противоположную границу: место, где computer output наконец становится частью человеческого опыта и где человеческое действие начинает обратный путь в system.

Human Interface подразумевается, потому что Модель не представляет напрямую тело, разум, внимание, эмоции, чувства, намерения, воспоминания или выбор пользователя. CatalystUI может описать, как system доставляет output к пользователю и как действие пользователя становится interaction input, но не делает вид, что моделирует всего человека. Это было бы слегка амбициозно. И ещё пугающе. Stack мощен, но ему не нужно становиться учебником психологии с прикрученным renderer.

### Получатель воспринимаемого output

В потоке сверху вниз Human Interface — получатель воспринимаемого output. Digital Data движутся через явный Stack, становятся интерпретированными, сформированными, организованными, отрендеренными, доставленными через window и перенесёнными system, пока наконец не могут быть восприняты. Когда этот output достигает чувств пользователя, явный Stack завершил свой нисходящий путь.

Это не значит, что пользователь получает Digital Data напрямую. Человек естественным образом не воспринимает единицы и нули, memory buffers, draw calls, audio samples или system events. Пользователь воспринимает результат работы system: свет, звук, вибрацию, движение, текст, пространственное изменение или другую форму сенсорного output. Human Interface — это место, где output перестаёт быть просто доставленным и начинает переживаться.

Это различие сохраняет честность Модели. System может предоставить output, но не может заставить понять. Дисплей может показать кнопку, динамик может воспроизвести звук, а устройство может завибрировать, но пользователь всё равно должен воспринять и интерпретировать этот результат как человек. Модель признаёт эту границу, не пытаясь определить каждый личный, биологический или контекстный фактор. Иными словами: CatalystUI может довести output до человека. Он не может заставить человека перестать игнорировать уведомление. Увы.

### Источник interaction

В потоке снизу вверх Human Interface — источник действия. Пользователь видит, слышит, чувствует, понимает, реагирует, решает и затем что-то делает. Это действие может быть нажатием клавиши, движением указателя, касанием экрана, произнесением команды, поворотом ручки, проходом через поле датчика или другим поведением, которое system может получить.

Само действие начинается вне явного Stack. Модель не описывает напрямую полный внутренний процесс, который привёл пользователя к действию. Она начинает моделировать обратный путь только тогда, когда system получает эффект этого действия. В этот момент действие становится interaction input и входит в Layer 1: Systems, где может быть передано вверх через Stack.

Это сохраняет ясное различие между **human action** и **system interaction**. Human action — это то, что делает пользователь. Interaction input — это то, что system получает от этого действия. Они тесно связаны, но не идентичны. Человек может намереваться нажать одно, а случайно нажать другое, или задеть клавишу, потянувшись за чем-то ещё. System может получить оба события, но только одно из них, вероятно, будет осмысленным выражением намерения пользователя. Если только случайный input не был целью; в таком случае поздравляем: интерфейс вошёл в очень экспериментальную фазу.

### Почему слой подразумевается

Human Interface подразумевается по той же причине, что и Data Storage: он требуется потоком, но не моделируется напрямую как явный слой преобразования. Stack зависит от пользователя, но не преобразует пользователя. Он не разбирает пользователя, не рендерит пользователя, не адаптирует пользователя и не хранит пользователя как component. Вероятно, так и лучше.

Вместо этого Модель рассматривает Human Interface как живую границу вокруг нижнего конца system. Явный Stack может описывать, как output подготавливается и доставляется, и может описывать, как полученное interaction движется вверх. Он останавливается до того, как заявить права на сам человеческий опыт.

Эта граница особенно важна, потому что пользователь — не просто ещё одно устройство. Дисплей предоставляет visual output. Клавиатура предоставляет input signals. Пользователь воспринимает, интерпретирует, выбирает, отвечает, ошибается в понимании, учится, колеблется, совершает ошибки и иногда с полной уверенностью нажимает не ту кнопку. Модель должна уважать это различие. Поэтому Human Interface присутствует, потому что Stack построен для человеческой коммуникации, но подразумевается, потому что человек не является частью процесса преобразования на стороне машины.

### Восприятие и намерение

Human Interface завершает коммуникационный цикл, соединяя восприятие и намерение. В одном направлении system предоставляет что-то воспринимаемое. В другом пользователь отвечает действием. Это создаёт разговорный цикл в центре CatalystUI: system говорит через output, пользователь отвечает через interaction, а system обрабатывает этот ответ, чтобы продолжить обмен.

Вот почему Human Interface нельзя свести к input devices. Keyboard, mouse, touchscreen, microphone, camera или controller могут помогать захватывать interaction, но ни одно из них не является пользователем. Это доступные system пути, через которые действие пользователя может войти в Stack. Human Interface — это человек, чьё восприятие и намерение придают этим сигналам смысл.

То же верно для output devices. Monitor, speaker, haptic motor или другое output device может переносить воспринимаемые данные, но устройство не завершает опыт. Опыт завершается, когда пользователь воспринимает результат. Экран, полный идеально отрендеренных pixels, всё ещё не является успешным интерфейсом, если пользователь не может увидеть, понять, достать, услышать, почувствовать или использовать то, что было предоставлено.

### Отношение к Systems

Human Interface находится прямо под **Layer 1: Systems**. Слой System предоставляет последнюю явную обработку output на стороне компьютера и первую явную обработку interaction на стороне компьютера. Human Interface находится за этим слоем как получатель output от system и источник действия пользователя.

Это отношение определяет нижний край Stack. В потоке сверху вниз system доставляет output к пользователю. В потоке снизу вверх system получает эффект действия пользователя. Поэтому system — последний явный слой машинной операции, а Human Interface — подразумеваемая граница, где машинная операция встречает человеческий опыт.

Разделяя эти слои, Модель избегает смешения поведения устройства с пользовательским опытом. System может знать, что клавиша была нажата, указатель сдвинулся или звук был воспроизведён. Он не знает автоматически, что пользователь понял, намеревался, почувствовал или заметил. Эти человеческие реальности находятся за пределами явного Stack, даже если Stack существует, чтобы служить им.

### Доступность и человеческое разнообразие

Human Interface также напоминает Модели, что пользователи — не взаимозаменяемые машины. Люди воспринимают и действуют через разные способности, чувства, контексты, инструменты, ограничения, предпочтения и среды. Один пользователь может в основном полагаться на visual output. Другой может зависеть от auditory output, tactile feedback, keyboard navigation, screen readers, captions, simplified motion, alternate input devices или других форм доступа.

Это не меняет структуру Stack. Это проясняет, почему Stack важен. Разделяя слои, CatalystUI может лучше определить, где происходит сбой, когда output доставлен, но не является осмысленно воспринимаемым, или когда у пользователя есть намерение, но нет пригодного пути выразить его. Граница Human Interface сохраняет видимой цель всего потока: system не просто производит output; он общается с человеком.

Этот человек может быть уставшим, рассеянным, блестящим, растерянным, иметь инвалидность, учиться, делать несколько дел сразу или пытаться закончить что-то за пять минут до дедлайна. Интерфейс всё равно должен встретить его как человека. Желательно без требования сначала прочитать сорокастраничное сообщение об ошибке.

### Почему слой важен

Human Interface не даёт Stack закончиться на машине. Без этого подразумеваемого слоя Модель остановилась бы на system output и system input, как будто цель интерфейса — просто перемещать сигналы через hardware. Это упустило бы суть. Цель Stack не только в производстве output; она в том, чтобы сделать возможной коммуникацию между информационной системой и пользователем.

Отделяя Human Interface от Systems, Модель сохраняет чистую финальную границу. Systems доставляет output и получает input. Human Interface воспринимает output и производит action. Явный Stack описывает машинный процесс между этими двумя направлениями, а подразумеваемый Human Interface напоминает, ради кого этот процесс существует.

Именно поэтому Human Interface принадлежит Stack, даже если не пронумерован. Пользователь — не слой, который нужно реализовать, отрендерить, разобрать или покрыть unit tests. Пользователь — причина, по которой слои существуют. И, если предположить, что пользователь человек, Модель работает прекрасно.
