# 5.8 The Stack :: Systems

## Подробное обсуждение

### Самый нижний явный слой

**Systems** — это самый нижний явный слой Stack. Этот слой представляет вычислительную среду, которая предоставляет базовые сервисы, устройства и операции, необходимые для доставки output и получения interaction. Там, где Layer 2 определяет ограниченный контекст, через который проходят output и interaction, Layer 1 представляет более широкую среду, которая делает этот контекст возможным.

System не следует понимать только как настольную операционную систему. В Модели CatalystUI system — это организованный набор процессов и возможностей платформы, поддерживающий интерфейс во время runtime. Это может быть традиционная операционная система, embedded environment, console, browser runtime, hardware platform или другой managed computing context. Определяющий признак — не категория продукта. Определяющий признак в том, что system предоставляет lower-level capabilities, через которые интерфейс действительно может работать.

### Операционная среда

Слой System предоставляет окружающую среду выполнения для явного Stack. Он может управлять hardware access, input devices, output devices, drivers, permissions, scheduling, memory, files, processes, windows, channels или другими platform-level services. Эти детали сильно различаются между реализациями, но все они выполняют одну концептуальную роль: позволяют интерфейсу соединяться с реальными возможностями машины или информационной системы.

Это отличает Layer 1 от Layer 2. Window — это ограниченный system-facing контекст, используемый интерфейсом. System — это более широкая среда, которая создаёт, владеет, распознаёт, ограничивает и обслуживает этот контекст. Window предоставляет конкретную точку соединения; system предоставляет мир, в котором это соединение существует.

Поэтому слой System не является просто пассивным основанием. Он активно участвует в цикле интерфейса. Он доставляет отрендеренный output к физическим или логическим устройствам, получает input от этих устройств, применяет правила платформы и раскрывает операции, на которые опираются верхние слои. Stack может описывать поток интерфейса, но system предоставляет операционную почву под этим потоком.

### Отношение к Windows

Systems и Windows тесно связаны, но это не один и тот же слой. Window получает отрендеренный output от Layer 3 и предоставляет ограниченный delivery context. System получает этот windowed output и выполняет нижнеуровневую работу, необходимую для доставки через доступные устройства или сервисы.

В потоке сверху вниз window передаёт output в system. System затем обрабатывает фактический путь доставки: отправляет visual output к дисплею, audio output к звуковому устройству, tactile output к haptic device, text output к terminal или другую форму output к соответствующему channel. Window определяет, где output принадлежит; system переносит его в среду, способную сделать его воспринимаемым.

В потоке снизу вверх system получает или обнаруживает interaction со стороны человека. Это может происходить через keyboard, pointer, touchscreen, microphone, controller, sensor, button или другой input path. System преобразует эту физическую или device-level активность в system-level signal, который может быть связан с window и передан вверх через Stack.

### Доставка output

Слой System — это последний явный этап потока сверху вниз. К тому моменту, когда output достигает Layer 1, верхние слои уже интерпретировали исходное представление, сформировали пригодные объекты интерфейса, организовали их в текущий операционный контекст, отрендерили этот контекст в output-ready форму и передали его через window. Теперь system выполняет platform-level work, необходимую для того, чтобы сделать этот output доступным Human Interface.

Это не значит, что сам system равен пользовательскому восприятию. Пользователь не воспринимает операционную систему напрямую. Пользователь воспринимает физический или сенсорный результат, доступный через устройства и каналы, управляемые system. Поэтому Layer 1 остаётся внутри процесса на стороне компьютера, а подразумеваемый Human Interface находится за ним как получатель output.

Это различие сохраняет точность Модели. System может произвести свет через дисплей, звук через динамики, вибрацию через мотор или другой воспринимаемый результат через устройство или сервис. System предоставляет последний явный механизм доставки; Human Interface получает и воспринимает результат.

### Происхождение interaction

Слой System также является первым явным этапом потока снизу вверх. Пользователь выполняет действие вне явного Stack, но system — это место, где это действие становится доступным моделируемому интерфейсу как interaction input. Само человеческое действие принадлежит подразумеваемому Human Interface. System получает эффект этого действия через поддерживаемый input path и начинает преобразовывать его во что-то, что Stack может обработать.

Вот почему system тесно связан с interaction. Физическое нажатие клавиши, движение указателя, touch gesture, spoken input, controller signal или sensor change сначала должны быть получены вычислительной средой, прежде чем верхние слои интерфейса смогут ответить. System обычно не определяет окончательный смысл этого interaction. Он определяет, что что-то произошло, предоставляет релевантный device или platform context и передаёт interaction к соответствующему window.

Оттуда interaction может двигаться вверх через Stack. Window связывает его с ограниченным контекстом, renderer может помочь перевести или сопоставить его, graph и frame могут маршрутизировать его, а соответствующий control наконец может его обработать. System начинает явный обратный путь, но смысл действия разрешается выше в Stack.

### Правила и ограничения платформы

Systems важны, потому что каждый интерфейс работает в рамках ограничений. System может определять, какие устройства доступны, как создаются windows, как доставляется input, как предоставляются permissions, как ведут себя output channels, к каким resources можно получить доступ и какие operations поддерживаются. Эти ограничения формируют то, что может делать остальная часть Stack.

Однако CatalystUI отделяет эти platform concerns от верхней модели интерфейса. Components не должны напрямую понимать каждый driver или правило operating system. Renderers не должны управлять каждой hardware detail. Windows не должны представлять всю платформу. Layer 1 предоставляет ясное место для system-level behavior, позволяя верхним слоям оставаться сосредоточенными на интерпретации, пригодности, организации и преобразовании.

Это разделение также позволяет Модели применяться в разных средах. Desktop application, mobile app, embedded device, browser-based interface, command-line tool или specialized hardware system могут иметь разные platform rules, но каждому всё равно нужен слой system, который предоставляет операционную среду под интерфейсом.

### Отношение к Human Interface

Systems находятся прямо над подразумеваемым **Human Interface**. Это значит, что Layer 1 — последний явный слой перед тем, как output покинет моделируемый поток на стороне компьютера, и первый явный слой после того, как действие пользователя войдёт в него. Поэтому system — это граница между управляемой вычислительной средой и человеком, который воспринимает и действует.

Эта граница существенна. Модель может описывать, как system отправляет output к устройству, но не моделирует напрямую сенсорный опыт пользователя, биологию, внимание, эмоции или интерпретацию. Точно так же Модель может описывать, как system получает input signal, но не моделирует напрямую полный человеческий процесс, породивший действие. Эти вопросы принадлежат подразумеваемому Human Interface.

Помещая Systems на Layer 1, Stack ясно определяет самую нижнюю явную точку, где процесс на стороне компьютера можно описать перед переходом к человеческому восприятию и действию.

### Почему слой важен

Systems удерживает Stack в реальной работе. Без этого слоя Модель описывала бы rendering и windows так, будто доставка output и получение input происходят автоматически. На практике каждый интерфейс зависит от базовой среды, которая управляет устройствами, resources, permissions, execution и platform behavior.

Отделяя Systems от Windows и Human Interface, Модель сохраняет чистую финальную границу. Windows предоставляет ограниченный контекст для output и interaction. Systems предоставляет базовую операционную среду, которая доставляет output и получает input. Human Interface воспринимает output и производит action. Это различие позволяет CatalystUI описывать интерфейсы на разных платформах и в разных доменах, не сводя system к одной operating system, конкретному device или visual display model.
