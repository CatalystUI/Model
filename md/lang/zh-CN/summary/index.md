# 2. 摘要

要理解用户界面如何工作，我们必须首先定义“_信息流_”。每天，不管人们是否意识到，他们都在与信息系统交互——可能是智能手机、计算机，或商店门口的门传感器（后面会进一步说明）。在每个系统中，信息被呈现，用户解释它，可能作出回应，然后系统处理这个回应。之后系统再次呈现信息，这个循环会在整个交互过程中重复。循环可以从任何一点开始：信息可能在用户能够解释它之前很久就已经被呈现，用户也可能在没有信息先被呈现的情况下作出回应。无论信息流何时或如何开始，同一个循环都适用。

CatalystUI Model 建立在这个信息流之上。它提供一种高层结构，用来描述信息如何在用户和信息系统之间流动，即使该系统看起来不像传统用户界面。换句话说，商店门口的传感器看起来可能像是几乎神奇地“感知”到了一个人，但信息流让这个过程变得简单：用户看到门口，识别前进路径，并进入检测区域。这个移动成为系统的输入。系统处理它，将开门作为可感知的输出，用户则通过走过去作出回应。短暂延迟后，系统关门，交换结束，直到另一个动作重新启动循环。

与信息流同时存在的是，_用户界面_定义了这个流在给定信息系统中如何发生。它决定系统如何接受输入、产生输出，并允许用户与之交互。由于每个系统都有不同需求，随着时间推移，人们发展出了许多描述和实现这些交互的方式，包括“human interfaces”（“HI”）、“human-machine interfaces”（“HMI”）和“human-computer interfaces”（“HCI”）。在现代计算机时代，这些接口最熟悉的形式就是“graphical user interface”（“GUI”）。

当我们比较不同实现时，一个共同模式开始浮现。尽管它们外在差异很大，我们仍然可以识别出出现在所有用户界面中的三个概念：1）“domains”，用于分类和组织数据；2）“the stack”，用于表示和解释数据；3）“connectors”，用于转换、修改和翻译数据。每个概念单独看都很有用，但合在一起，它们形成了一个_可逆_的_系统_，既能描述整个界面，也能描述单个过程。这正是 CatalystUI Model 的力量所在：通过把交互分解为分类、表示和翻译，它让信息系统更容易解释、调试和理解。
