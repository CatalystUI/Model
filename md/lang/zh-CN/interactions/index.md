# 7. Interactions

## 高层概览

到这里，我们已经可以通过 CatalystUI Model 比以前更清楚地描述用户界面。我们可以识别信息流，把信息分类到 domains，追踪它穿过 Stack，并解释 connectors 如何把它从一层移动和转换到下一层。这样做时，用户界面背后的许多神秘感开始消散。我们能看到信息从哪里开始、到哪里去、如何变化，以及最终如何到达用户。

那么，我们完成了吗？还没有。还有一个关键拼图尚未完全处理：_你！_

任何用户界面最重要的部分，是使用它的人。没有用户，界面就失去了目的。那时我们只是在描述一台机器与另一台机器通信，例如服务器向 API 发送数据，或一个程序把指令传给另一个程序。这些交换可能有用，但并不是 Model 的完整主题。用户界面之所以存在，是因为一个人需要感知、理解、选择某物，或以某种方式回应。即使你的猫跳上键盘，召唤猫神，并把地球归还给它们合法的王座，重点仍然一样：系统之外的某物对系统采取了行动，而界面现在必须回应。

这就是为什么“Human Interface”很重要。我们已经把它识别为 Stack 底部的隐含端点，但现在需要更仔细地看那里发生了什么。信息并不是到达用户后就停止。用户可以回应。他们可以点击、说话、移动、打字、聆听、忽略、犹豫、误解，或以系统没有预期的方式行动。这个回应成为信息流的一部分。

因此，我们还需要识别并跟踪另一种数据：_interaction_。interaction 是当信息到达用户、用户回应、系统把这个回应作为持续信息流的一部分接收时发生的交换。它是 Model 不再只是关于呈现，而是关于参与的那个点。界面不再只是向人显示信息；它允许这个人影响接下来发生的事。

更直接地说，_interaction 是动作背后的意图_。点击、轻触、滑动、命令、移动或说出的话只是它可见的一部分。在动作背后，是用户正在_试图_做的事情。他们想打开菜单、向前移动、提交表单、暂停歌曲、关闭警告、打开灯，或者只是弄清楚发生了什么。系统可能只接收到一个信号，但用户并不只是发送信号。用户是在提出请求。

### 技术带来的现代挫败感

许多现代技术挫败感正是从这里开始的。用户带着某个意图行动，但系统错误解释了这个意图、回应太慢，或完全忽略它。我们都感受过：一个看起来可以点击却什么都不做的按钮，一个看起来冻结的页面，一个听到了我们却没有理解我们的设备，或一个技术上工作了却没有以我们能感知的方式回应的界面。在每一种情况下，用户都提出了请求，但系统没有清楚回答。当这种情况发生时，挫败感并不神秘。它是 interaction 被误解、延迟或悬而未决的自然结果。

这就是 interactions 如此特别的原因。不同于许多其他形式的数据，它们既是双向的，也是转换性的。它们从系统移动到用户，再从用户回到系统。它们在移动中改变。开始作为 output 的东西可能变成 perception，perception 可能变成 intent，intent 可能变成 action，而 action 可能变成 input。系统随后可以回应，再次开始循环。这使 interaction 不同于存储文件、渲染图像或单一声音。interaction 不只是被带到某处的数据。它是由选择塑造的数据。

从这个意义上说，interactions 指向深刻的人性。我们不是被动接收信息的机器。我们注意、好奇、选择、犹豫、误解、纠正自己、再次尝试，有时还会连续按同一个按钮十七次，因为_这次肯定_会成功。interaction 之所以存在，是因为人拥有 agency。它由用户选择的能力，以及系统接收并回应这个选择的能力来定义。没有选择，就没有真正的 interaction。只有 output。

当然，机器也可以塑造交换。在很多情况下，interaction 从系统向用户呈现某物开始：屏幕、声音、提示、警告、震动、门口或其他信号。系统也可以通过拒绝输入、关闭窗口、超时或忽略请求来停止交换。但即便如此，interaction 也没有真正消失。如果系统不回应，用户可能等待、重试、困惑、沮丧、离开、重启设备，或决定再也不用这个程序。借用运动的语言来说，一个动作不会仅仅因为系统拒绝继续它而消失。用户仍然在移动。体验仍然在变化。信息流仍然重要。

这就是为什么用户界面不能被设计成好像计算机是宇宙中心。它们不是。计算机存在，是为了服务人的目的。它们帮助我们创造、学习、组织、交流、敬拜、建造、想象，并解决那些原本无法触及的问题。当界面忘记用户时，它会变得冰冷、令人沮丧且不必要地困难。但当它尊重用户的意图、清楚回应，并把信息带过正确路径时，技术就开始不像一堵墙，而更像一个工具。

这就是 CatalystUI Model 的核心。它给我们一种方式来看见完整旅程：被存储的信息、它所属的 domains、它穿过的层、转换它的 connectors，以及把它带回最初发起交换之人的 interaction。它帮助我们停止把用户界面当作一堆互不相干的 widgets、windows、APIs、renderers 和 devices，而是把它们识别为_人_与_机器_之间完整的通信系统。

### 一切背后的目的

多年来，梦想很简单但顽固：技术不应该必须感觉这么破碎。一个程序不需要为了给我们一种清楚的机器交互方式，就变得臃肿、脆弱或受限于平台。一个 framework 不需要把简单想法藏在一层层混乱后面。用户界面不需要强迫人像计算机一样思考。重要的是，计算机应当被设计成理解人。CatalystUI 存在，是因为这个梦想并非不可能。它只是需要一个足够清楚的模型来描述真正发生了什么。

Stack 给我们结构。Domains 告诉我们正在处理哪种信息。Connectors 解释信息如何移动和变化。Interactions 提醒我们为什么这一切一开始就重要。它们共同形成一种方式，让我们重新围绕人来设计计算机：不是围绕趋势，不是围绕 frameworks 的任意决定，不是围绕别人_告诉_我们要接受的限制，而是围绕人与系统之间_真实的信息流_。

这就是 CatalystUI Model 如此重要的原因。这就是为什么多年的工作、爱、心血、恨、挫败和希望都倾注其中。这也是为什么我很高兴你在这里。欢迎来到 Catalyst 宇宙。我很高兴你能陪我走过这段冒险的一小部分。希望它至少让你对世界的感知有一小块变得更好。
