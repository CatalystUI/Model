# 4.4 Domains :: Tactile

## 深入讨论

在视觉和听觉之后，**tactile** domain 描述的是被塑造成可供触觉感知的数据。触觉数据是为了被身体感知而存在的信息：振动、压力变化、凸起表面，或用户通过身体接触来理解的另一种输出形式。visual data 是被看见的，auditory data 是被听见的，而 tactile data 是被感觉到的。

tactile domain 经常与 haptics 联系在一起，但它超出了简单振动。可刷新的盲文显示器、实体按钮按压，或控件中的阻力，都可以参与触觉沟通。在每种情况下，系统都不只是把信息呈现在用户附近；它是在通过身体感觉进行沟通。

触觉数据特别有意思，因为触觉与行动紧密相连。视觉和听觉可以远距离沟通，但触觉信息通常需要接触、压力、运动或阻力。这使触觉交互感觉直接而具身。用户不只是观察系统；在许多情况下，用户是在身体上与系统相遇。

### 理解触觉数据

理解触觉数据的一个有用方式，是考虑 **接触**、**强度** 和 **模式**。它们不是模型中的正式类别，但有助于解释触觉如何承载意义。

**接触** 描述用户与输出之间的身体关系。触觉信号通常需要某个连接点，例如放在表面上的手指，或握住设备的手。因此，触觉数据通常取决于用户正在触摸哪里、握着什么设备，以及系统是否能通过这种接触清晰地传递感觉。

**强度** 描述触觉信号的力量或力度。轻微感觉可以传达确认，而更强的感觉可以传达紧迫性。控件中的阻力可以暗示边界、限制或过渡。强度很重要，因为触觉可以不依赖复杂细节进行沟通；有时感觉的强度 *就是* 消息。

**模式** 描述触觉信息如何随时间变化。单次脉冲、重复节奏、持续振动或凸起排列都可以承载不同意义。模式让触觉能够传达时机、区分、方向或身份。

### 触觉意义

触觉输出通过身体感觉表达意义。振动可以确认某个动作已经发生。凸起形状可以表示一个字符。力反馈可以传达用户已经到达某个限制。感觉是可感知的形式，而意义来自系统使用这种感觉的目的。

这使触觉设计特别依赖一致性。用户会通过重复体验很快学会某种身体模式意味着什么。如果同一种感觉被不一致地使用，它就会变得更难信任。当感觉与其代表的事件、状态或动作之间有清晰关系时，触觉信息效果最好。

触觉数据还有一种独特优势：它可以安静而私密地沟通。细微信号可以在没有声音的情况下通知用户。触觉界面可以在不要求视觉或语音的情况下呈现信息。实体控件可以引导用户的手，而不要求用户把视线从正在做的事情上移开。这使 tactile domain 在视觉注意力有限、听觉输出会造成干扰，或触觉是最直接沟通方式时很有价值。

### 触觉数据与无障碍

tactile domain 对无障碍非常重要，因为当视觉或听觉不可用、受限或不适合时，它可以承载意义。触觉输出可以让 symbolic information 通过触摸变得可感知。反馈可以在不要求用户看到视觉变化的情况下确认动作。实体控件可以通过形状、纹理和位置提供方向感。

当触觉被视为有意义的 domain，而不是最后添加的小效果时，触觉无障碍最强。触觉信号可以支持另一种输出形式，但它也可以独立承载信息。实体界面可以被设计成让用户在视觉参与之前先通过触摸理解它。当触觉信息被有意规划时，系统会对更多人、在更多情境中变得更容易使用。

tactile domain 也揭示了意义何时过度依赖触觉本身。如果确认只作为身体信号存在，而设备没有与用户接触，它可能会被错过。如果用户感觉能力降低，或设备无法产生预期反馈，触觉提示可能会失败。domains 帮助识别意义正由哪里承载，以便在需要时用另一种形式表示相同意图。

### 更广泛体验中的触觉数据

触觉数据通常在与其他 domains 配对时效果最好。系统可以在视觉或听觉变化之外提供身体反馈，从而强化正在发生的事情。在这些情况下，触觉通过让系统感觉像是身体上存在，来加强体验。

当触觉信息与视觉和声音整合时，它可以成为更大 multisensory exchange 的一部分。触觉部分仍然有自己的角色：它告诉我们体验中哪一部分是为了被感觉到。这一区分很重要，因为一个系统可能看起来清楚、听起来清楚，却仍然没有在身体层面沟通；或者它可能有效使用触觉，同时依赖另一个 domain 提供细节。

简而言之，tactile domain 描述的是被塑造成可感觉输出的信息。它帮助解释系统如何使用接触、强度和模式，通过身体进行沟通。当触觉数据被妥善处理时，用户可以感受到系统正在表达什么，识别有意义的反馈，并以更强的信心回应交互。
