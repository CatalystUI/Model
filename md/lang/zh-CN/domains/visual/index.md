# 4.2 Domains :: Visual

## 深入讨论

如果说 **symbolic** domain 描述的是数据尚未绑定到某个具体感官之前的状态，那么 **visual** domain 描述的就是数据已经被塑造成可供观看的状态。视觉数据是为了被看见而存在的信息：一张图像、渲染后的文本，或一个可见控件。关键区别不在于这些数据“将来是否可能”出现在屏幕上，而在于它们在当前交互中的作用是否是通过视觉来沟通。

这意味着视觉数据不应与其背后的存储形式混淆。包含图像数据的文件，只要还只是作为存储信息存在，它仍然是 symbolic。一个文本段落只要还只是字符、标记或另一种抽象表示，它也仍然是 symbolic。当系统以用户可以看见并解释的形式呈现它时，它才变成 visual。变化并不是数据变得更重要；变化在于它的沟通方式已经从表示转向了感知。

视觉数据特别常见，因为视觉可以同时传达许多关系。大小、颜色、间距、方向、分组和运动都能帮助用户理解某个东西是什么、属于哪里，以及是否可以对它采取行动。这就是为什么视觉界面常常显得很直接。用户可以扫一眼窗口、网页或游戏场景，在读完每个字之前就获得意义。系统不只是在展示数据；它是在把数据组织成一种可见体验。

### 理解视觉数据

理解视觉数据的一个有用方式，是考虑 **位置**、**外观** 和 **状态**。它们不是 CatalystUI Model 中正式的子 domain，也不是必需分类，但它们提供了一种实用方式，帮助我们识别视觉信息如何传达意义。

**位置** 描述视觉数据出现在哪里，以及它如何与周围的信息相关联。放在段落上方的标题会传达归属关系。放在表单附近的按钮会传达关联关系。覆盖在其他内容之上的菜单会传达临时优先级。位置很重要，因为用户不会孤立地感知可见对象；他们会感知可见对象之间的关系。

**外观** 描述视觉数据如何向用户呈现自身。形状、颜色、字体排印、对比度和图像都会影响用户认为自己正在看什么。一段文本可能根据样式而看起来像标题、警告或链接。一个矩形可能根据边框、间距和周围上下文而看起来像按钮、面板或装饰。外观赋予视觉数据可被识别的形式。

**状态** 描述当前通过视觉传达的条件。一个控件可能显示为活跃、禁用、已选择、获得焦点、加载中或隐藏。这些状态很重要，因为用户的下一步行动往往取决于界面看起来准备做什么。如果视觉状态与系统的实际条件不一致，即使底层逻辑在技术上是正确的，界面也会变得令人困惑。

### 视觉意义

视觉输出表达意义，但它不应被误认为意义本身。红色边框可以传达某处有问题，但边框不是错误本身。图标可以代表一个动作，但图标不是动作本身。布局可以展示层级，但布局不是底层结构本身。视觉数据是意义的感官表达，而不是意义的完整来源。

这种区分有助于避免一个常见的设计错误：把太多责任放在某个东西的外观上，却没有保留它真正表达的意义。如果界面只依赖颜色来传达错误，意义就被困在单一的视觉信号里。如果图标没有支持性的标签、描述或可访问意义，系统可能看起来干净，却变得更难理解。当可见形式忠实表达底层意图时，视觉清晰度才最强。

视觉数据还带有一种独特风险，因为用户往往相信自己看到的东西。如果某个东西看起来可以点击，用户就会期待它作出响应。如果某个东西看起来被禁用，用户就会期待它不作响应。如果某个东西看起来被选中，用户就会期待系统把它当作已选中处理。当可见呈现与实际行为不一致时，即使程序完全按照写好的逻辑运行，用户也会把界面体验为坏掉了。

### 视觉数据与无障碍

visual domain 让无障碍更容易被推理，因为它指出了信息何时只通过视觉来传达。如果错误只用颜色显示，图表只用图像呈现，或者进度只用动画表示，那么意义可能并不是对每个用户都可用。问题不在于视觉沟通不好；问题在于视觉沟通可能需要被翻译成另一种形式。

这正是 domains 作为诊断工具变得有用的地方。它们帮助我们询问意义目前存在于哪里。它只是 visual 吗？它也能以 symbolic 形式表示吗？它是否应该通过声音、触觉或另一种输出形式提供？通过回答这些问题，开发者可以在不同感知方式之间保留相同意义，而不是把无障碍当作事后补丁。

### 更广泛体验中的视觉数据

视觉数据也可以参与并非纯视觉的体验。视频播放器可能把动态图像与声音结合起来。游戏可能结合图形、音乐和控制器反馈。操作系统可能把窗口、警报和输入设备组合成一个更大的交流过程。在这些情况下，visual domain 识别体验中面向视觉的部分，而其他 domains 则描述所涉及的其他感知形式。

这让模型保持精确。视觉界面并不自动等于整个用户界面，多感官体验也不会抹去其中的视觉部分。每个 domain 都帮助识别意义是如何被承载的。visual domain 回答一个具体问题：哪些信息正在被塑造成用户可以看见的形式？

简而言之，visual domain 描述的是从 symbolic representation 到可由视觉读取的输出之间的移动。它让我们能够讨论可见信息，而不必把所有界面都简化成图形。当视觉数据被妥善处理时，用户可以识别系统正在呈现什么，理解哪些东西可以被操作，并自信地作出回应。
