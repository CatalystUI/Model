# 4.3 Domains :: Auditory

## Uitgebreide bespreking

Na het visual domain beschrijft het **auditory** domain data die voor gehoor is gevormd. Auditory data is informatie die bedoeld is om via geluid te worden waargenomen: gesproken woorden, muziek, waarschuwingen, tonen of elke andere output die de gebruiker begrijpt door te luisteren. Waar visual data betekenis rangschikt in een vorm die door zicht kan worden gelezen, rangschikt auditory data betekenis in tijdgebaseerd geluid.

Dit maakt het auditory domain op een belangrijke manier anders dan het visual domain. Visuele informatie kan vaak in één oogopslag worden gescand, maar auditieve informatie ontvouwt zich meestal in de tijd. Een gebruiker kan naar een scherm kijken en meerdere relaties tegelijk herkennen, maar een geluid moet in volgorde worden gehoord. Daarom is auditory data sterk afhankelijk van timing, volgorde, duur en ritme. De betekenis zit niet alleen in wat wordt gehoord, maar ook wanneer het wordt gehoord en hoe het verandert.

Een opgeslagen audiobestand is niet auditory alleen omdat het geluidsdata bevat. Zolang het opgeslagen, gecodeerd of abstract vertegenwoordigd blijft, is het nog steeds symbolic. Het wordt auditory wanneer het systeem het produceert als waarneembaar geluid. Hetzelfde geldt voor geschreven tekst die door een screenreader wordt voorgelezen, een melding die wordt vertaald naar een klank, of een game-event dat door muziek wordt uitgedrukt. In elk geval heeft het systeem informatie genomen en aan gehoor verbonden.

### Auditory data begrijpen

Een nuttige manier om auditory data te begrijpen is te kijken naar **inhoud**, **timing** en **toon**. Dit zijn geen formele categorieën van het Model, maar ze helpen uitleggen hoe geluid betekenis anders draagt dan zicht.

**Inhoud** beschrijft wat het geluid communiceert. Bij gesproken output kunnen dit de woorden zijn die worden gelezen. Bij muziek kan het melodie, harmonie of progressie zijn. Bij een melding kan het het herkenbare patroon zijn dat de gebruiker vertelt dat er iets is gebeurd. Auditieve inhoud is de substantie van wat de gebruiker geacht wordt te horen en te begrijpen.

**Timing** beschrijft wanneer het geluid gebeurt en hoe lang het duurt. Een waarschuwingstoon die te laat wordt afgespeeld kan zijn nut verliezen. Een gesproken bericht dat te snel gaat kan moeilijk te volgen zijn. Muziek die onmiddellijk op een gebruikersactie reageert kan verbonden voelen, terwijl vertraagd geluid het systeem losgekoppeld kan laten voelen. Timing doet ertoe omdat auditory data in beweging wordt ervaren.

**Toon** beschrijft de kwaliteit of het karakter van het geluid. Een zachte klank, een scherpe piep en een rustige stem kunnen heel verschillende betekenissen communiceren, zelfs als het allemaal korte auditieve signalen zijn. Toon helpt de gebruiker urgentie, stemming, bevestiging, waarschuwing of voltooiing begrijpen. Het geeft geluid zijn emotionele en praktische karakter.

### Auditory betekenis

Auditieve output drukt betekenis uit via geluid, maar het geluid zelf moet niet worden aangezien voor de hele betekenis. Een waarschuwingspiep kan een probleem communiceren, maar de piep is niet het probleem. Een gesproken label kan tekst communiceren, maar de stem is niet de onderliggende structuur. Een muzikale cue kan succes, gevaar of overgang communiceren, maar de betekenis komt uit hoe het systeem die cue binnen de ervaring gebruikt.

Dit onderscheid is belangrijk omdat geluid krachtig kan zijn zonder precies te zijn. Een korte toon kan de aandacht van de gebruiker trekken, maar niet uitleggen wat er gebeurde. Een gesproken bericht kan duidelijk uitleggen, maar duurt langer dan een visuele cue. Muziek kan het gevoel van een ervaring vormen, maar geeft misschien geen exacte instructies. Auditief ontwerp is het sterkst wanneer het geluid past bij het soort betekenis dat het systeem moet uitdrukken.

Auditory data beïnvloedt de gebruiker ook anders dan visual data omdat geluid de gebruiker kan bereiken zonder dat die rechtstreeks naar het systeem kijkt. Een timer kan vanuit een andere kamer afgaan. Een navigatie-app kan spreken terwijl de ogen van de gebruiker op de weg blijven. Een screenreader kan iemand software laten bedienen zonder van zicht afhankelijk te zijn. Daardoor is het auditory domain bijzonder waardevol wanneer aandacht verdeeld is, zicht niet beschikbaar is, of geluid het duidelijkste communicatiepad is.

### Auditory data en toegankelijkheid

Het auditory domain is centraal voor toegankelijkheid omdat het informatie kan dragen die anders visueel opgesloten blijft. Tekst kan worden uitgesproken. Interfacetoestand kan worden aangekondigd. Navigatie kan via geluid worden begeleid. Voor sommige gebruikers is auditieve output geen verbetering, maar de primaire manier waarop het systeem bruikbaar wordt.

Tegelijk kan auditieve informatie ook toegankelijkheidsproblemen veroorzaken wanneer zij de enige manier is waarop betekenis wordt gecommuniceerd. Een waarschuwing die alleen als geluid bestaat kan worden gemist door een dove of slechthorende gebruiker. Een gesproken instructie kan moeilijk te volgen zijn in een lawaaierige omgeving. Een geluidseffect kan een actie bevestigen, maar als er geen andere representatie van die bevestiging is, wordt de betekenis volledig afhankelijk van gehoor.

Hier helpen domains laten zien wat het systeem werkelijk doet. Als belangrijke betekenis alleen door geluid wordt gedragen, kan de ontwikkelaar vragen of die ook symbolisch, visueel, tactiel of op een andere manier beschikbaar moet zijn. Het doel is niet om auditief ontwerp te verzwakken, maar om betekenis te bewaren over de manieren waarop gebruikers het systeem echt waarnemen.

### Auditory data in bredere ervaringen

Auditory data werkt vaak samen met andere domains. In een videospeler kan geluid spraak of muziek dragen terwijl visuals beweging dragen. In een game kan audio afstand, gevaar, sfeer of feedback communiceren. In een besturingssysteem kan geluid meldingen, fouten en bevestigingen ondersteunen. In elk geval identificeert het auditory domain het deel van de ervaring dat voor gehoor is gevormd.

Wanneer geluid wordt geïntegreerd met andere vormen van waarneming, kan het deel worden van een grotere multisensory uitwisseling. Een geluid gekoppeld aan een visuele animatie kan een actie voltooid laten voelen. Een gesproken richting gekoppeld aan een kaart kan de gebruiker duidelijker begeleiden dan beide vormen alleen. Een trilling gekoppeld aan een meldingstoon kan een melding moeilijker te missen maken. Het auditieve deel heeft nog steeds zijn eigen rol, maar de volledige ervaring kan afhangen van hoe domains samenwerken.

Kort gezegd beschrijft het auditory domain informatie die is gevormd tot hoorbare output. Het helpt uitleggen hoe systemen geluid gebruiken om inhoud, timing, toon en feedback te communiceren. Wanneer auditory data goed wordt behandeld, kan de gebruiker horen wat het systeem presenteert, herkennen wat er is veranderd, en reageren zonder dat elk deel van de ervaring zichtbaar hoeft te zijn.
