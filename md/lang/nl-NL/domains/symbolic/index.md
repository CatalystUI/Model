# 4.1 Domains :: Symbolic

## Uitgebreide bespreking

Het **symbolic** domain beschrijft data voordat die is vastgelegd aan een specifiek zintuig. Symbolic data is informatie die nog niet primair bedoeld is om gezien, gehoord, gevoeld, geroken of geproefd te worden. Zij bestaat als representatie: tekst, bytes, markup, configuratie, bestanden, berichten, protocollen, identifiers, of andere vormen die betekenis dragen zonder zelf al een zintuiglijke output te zijn.

Dit maakt symbolic data een van de belangrijkste domains in het Model. Veel informatie begint symbolisch. Een tekstbestand is niet automatisch visual omdat het ooit op een scherm kan verschijnen. Een audiobestand is niet automatisch auditory zolang het alleen gecodeerde data in opslag is. Een afbeelding is niet automatisch visual zolang het systeem haar alleen als bytes behandelt. De data wordt pas zintuiglijk wanneer het systeem haar in een vorm plaatst die de gebruiker via dat zintuig kan waarnemen.

### Symbolic data begrijpen

Symbolic data draait om representatie. Zij kan betekenis bevatten, maar die betekenis is nog niet aan één manier van waarnemen verbonden. Dezelfde symbolische data kan op verschillende manieren worden uitgedrukt. Tekst kan worden weergegeven op een scherm, voorgelezen door een screenreader, afgedrukt op papier, of omgezet naar braille. Een configuratiebestand kan een instellingenpagina, een command-line output of een geautomatiseerd proces aandrijven. De symbolic vorm blijft de bronrepresentatie, terwijl de uiteindelijke output door een ander domain kan worden gedragen.

Daarom is symbolic niet “minder echt” dan visual of auditory. Het beschrijft alleen een eerder stadium in de informatiestroom. De data heeft betekenis, maar die betekenis wacht nog op een kanaal waardoor zij voor de gebruiker kan worden uitgedrukt.

### Symbolic betekenis

Symbolic output en symbolic representatie moeten voorzichtig worden onderscheiden. Een zin in een Markdown-bestand heeft betekenis, maar die betekenis is nog niet hetzelfde als de zichtbare tekst die op een webpagina verschijnt. De zichtbare tekst is visual. De Markdown die haar beschrijft is symbolic. Op dezelfde manier kan een knopbeschrijving symbolisch bestaan voordat zij wordt geparsed naar een component en gerenderd als zichtbaar of auditief element.

Dit onderscheid helpt voorkomen dat systemen hun opgeslagen representatie verwarren met de ervaring van de gebruiker. Het feit dat betekenis in een bestand staat, betekent niet dat de gebruiker haar kan waarnemen. Het feit dat een label in data bestaat, betekent niet dat het label toegankelijk is. Het Model vraagt daarom steeds: in welke vorm bestaat deze informatie nu, en hoe wordt zij uiteindelijk waargenomen?

### Symbolic data en toegankelijkheid

Het symbolic domain is bijzonder belangrijk voor toegankelijkheid omdat symbolic data vaak het punt is waarop betekenis nog naar meerdere vormen kan worden vertaald. Als een systeem de betekenis alleen in een visuele vorm bewaart, kan die betekenis moeilijker naar andere kanalen worden gebracht. Als de betekenis symbolisch helder is, kan zij gemakkelijker worden weergegeven, voorgelezen, getrild, beschreven of op een andere manier beschikbaar worden gemaakt.

Een goed ontworpen interface bewaart dus niet alleen hoe iets eruitziet, maar ook wat het betekent. Een icoon kan een visuele vorm hebben, maar heeft ook een symbolische naam of beschrijving nodig. Een waarschuwing kan rood worden weergegeven, maar moet ook symbolisch herkenbaar zijn als waarschuwing. Zo kan dezelfde intentie door verschillende domains worden gedragen.

### Symbolic data in bredere ervaringen

Symbolic data werkt vaak als het beginpunt voor andere domains. Een documentstructuur kan visuele pagina’s produceren. Een tekstbericht kan auditieve spraak worden. Een commando kan een tactiele bevestiging veroorzaken. In elk geval blijft het symbolic domain nuttig omdat het de zintuigneutrale betekenis identificeert voordat die betekenis in een specifieke ervaring wordt geplaatst.

Kort gezegd beschrijft het symbolic domain informatie als representatie vóór zintuiglijke plaatsing. Het helpt ons onderscheid maken tussen betekenis die in data bestaat en betekenis die daadwerkelijk aan de gebruiker wordt aangeboden. Wanneer symbolic data helder wordt behandeld, kan dezelfde informatie betrouwbaarder worden vertaald naar de vormen waarin mensen haar zien, horen, voelen of anderszins ervaren.
