# 5.6 The Stack :: Renderers

## بحث عمیق

### لایه تبدیل به خروجی

**Renderers** لایه‌ای است که داده آماده‌شده را به شکلی تبدیل می‌کند که بتواند به خروجی قابل ادراک برسد. در کاربرد سنتی، renderer اغلب به گرافیک مربوط می‌شود؛ مانند OpenGL، Vulkan، Metal یا Direct3D. اما در CatalystUI، renderer می‌تواند در هر دامنه‌ای وجود داشته باشد.

یک renderer بصری ممکن است geometry، text، images یا draw commands تولید کند. یک renderer صوتی ممکن است samples، waveforms یا دستورهای پخش ایجاد کند. یک renderer لمسی ممکن است الگوهای haptic تولید کند. هدف مشترک همه آن‌ها تبدیل داده آماده‌شده به شکلی است که window و system بتوانند آن را تحویل دهند.

### Renderer خودش مقصد نیست

Renderer خروجی نهایی را مستقیماً به کاربر نمی‌دهد. برای این کار باید از Layer 2 و Layer 1 عبور کند. Renderer ممکن است داده را آماده کند، اما window زمینه تحویل را فراهم می‌کند و system آن را از طریق دستگاه‌ها یا سرویس‌های واقعی به کاربر می‌رساند.

این تمایز مهم است. اگر renderer را با window یا system یکی بگیریم، کنترل دقیق مدل از بین می‌رود. Renderer مسئول تبدیل است، نه مالکیت پنجره، مدیریت دستگاه یا اجرای سیستم‌عامل.

### تبدیل در دامنه‌های مختلف

در Visual، rendering ممکن است شامل rasterization، layout text، compositing، shading یا تولید frame buffer باشد. در Auditory، ممکن است شامل mixing، resampling، effects یا تولید samples باشد. در Tactile، ممکن است شامل تبدیل یک interaction یا state به الگوی لرزش باشد.

با وجود تفاوت‌های فنی، مدل مفهومی ثابت است: renderer داده را از شکل سازمان‌یافته Stack به شکل آماده‌تحویل تبدیل می‌کند.

### مسیر برگشتی interaction

گاهی renderer در مسیر interaction نیز نقش دارد. برای نمونه، یک renderer بصری ممکن است مختصات system را به مختصات content تبدیل کند، hit testing را پشتیبانی کند یا interaction را به فرمی تبدیل کند که graph بتواند آن را مسیریابی کند. این به معنای آن نیست که renderer باید منطق control را انجام دهد؛ بلکه فقط ممکن است ترجمه لازم میان output-space و interface-space را فراهم کند.

### جداسازی قدرت است

وقتی renderer از graph، component و window جدا باشد، می‌توان پیاده‌سازی‌های متفاوتی را جایگزین کرد. همان componentها ممکن است با renderer متفاوت روی پلتفرمی دیگر کار کنند. همین جداسازی یکی از نقاط اصلی قدرت CatalystUI است: rendering یک مرحله مشخص است، نه یک توده درهم از داده، رفتار، پنجره و سخت‌افزار.
