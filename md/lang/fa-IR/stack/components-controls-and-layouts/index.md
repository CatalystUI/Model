# 5.4 The Stack :: Components, Controls, & Layouts

## بحث عمیق

### لایه استفاده و تعامل

**Components, Controls, & Layouts** لایه‌ای است که داده تفسیرشده به چیزهایی تبدیل می‌شود که برنامه و کاربر می‌توانند با آن‌ها کار کنند. Layer 6 داده را قابل فهم می‌کند؛ Layer 5 آن را قابل استفاده، قابل تغییر، قابل تعامل و قابل سازمان‌دهی می‌کند.

این لایه معمولاً mutable است. رابط‌های کاربری زنده‌اند: کاربر کلیک می‌کند، مقدارها تغییر می‌کنند، صدا پخش و متوقف می‌شود، متن ویرایش می‌شود، حالت فعال یا غیرفعال می‌شود، و layout دوباره محاسبه می‌گردد. Layer 5 جایی است که این پویایی وارد مدل می‌شود.

### Components

یک **Component** عنصر قابل استفاده‌ای است که نمای انسانی‌تر و برنامه‌نویسانه‌تر از داده یا رفتار ارائه می‌دهد. Component ممکن است یک قطعه متن، تصویر، فایل صوتی، شکل، ورودی، بخش پیکربندی یا هر واحد دیگری باشد که سیستم می‌تواند با آن کار کند.

Componentها معمولاً properties و methods دارند. برای نمونه، یک component بصری ممکن است `Size`، `Position` و `Color` داشته باشد. یک component صوتی ممکن است `Play()`، `Pause()` و `Stop()` داشته باشد. نکته این است که component داده را به چیزی تبدیل می‌کند که توسعه‌دهنده می‌تواند به شکل مستقیم‌تر با آن کار کند.

### Controls

یک **Control** نوعی component است که تعامل را مستقیم مدیریت می‌کند. اگر component «چیزی برای کار کردن» باشد، control «چیزی برای پاسخ دادن» است. دکمه، فیلد متن، slider، کنترل صوتی یا حتی دکمه فیزیکی می‌تواند control باشد، اگر interaction را دریافت کند و به آن پاسخ دهد.

Controls معمولاً مقصد نهایی بسیاری از interactions هستند. یک کلیک ممکن است از system به window، renderer، frame و graph عبور کند، اما در نهایت باید به control مناسب برسد تا تصمیم بگیرد چه کاری انجام شود.

### Layouts

یک **Layout** componentای است که componentهای دیگر را بر اساس نظم یا رابطه‌ای مشخص مرتب می‌کند. Layout الزاماً کنترل تعاملی نیست. نقش آن سازمان‌دهی است: vertical stack، horizontal stack، grid، audio collection، playlist، group یا هر ساختاری که عناصر دیگر را در یک ترتیب قرار دهد.

Layout می‌تواند بصری باشد، اما محدود به visual نیست. یک layout صوتی ممکن است افکت‌های صوتی را دسته‌بندی کند. یک layout لمسی ممکن است الگوهای بازخورد را مرتب کند. اصل موضوع، نظم دادن به components است.

### جایی که تعامل معنا پیدا می‌کند

Layer 5 جایی است که Interaction Data اغلب به تغییر معنادار تبدیل می‌شود. وقتی کاربر روی دکمه کلیک می‌کند، متنی را وارد می‌کند یا پخش صوت را متوقف می‌کند، control مناسب تصمیم می‌گیرد این تعامل چه معنایی دارد. ممکن است no-op باشد، ممکن است داده را بخواند، مقدار جدیدی ایجاد کند، چیزی را به‌روزرسانی کند یا داده‌ای را حذف کند.

به همین دلیل، این لایه مرز مهمی میان «تفسیر داده» و «کار با داده» است. Structure می‌گوید داده چه هست؛ component و control می‌گویند با آن چه می‌توان کرد.
