# 5.7 The Stack :: Windows

## بحث عمیق

### لایه تحویل bounded

**Windows** لایه‌ای است که خروجی renderشده زمینه‌ای bounded برای تحویل دریافت می‌کند. Layer 3 وضعیت آماده خروجی را تولید می‌کند، اما آن خروجی هنوز به مکان، کانال یا نمای مشخصی نیاز دارد تا system بتواند آن را ارائه کند. Layer 2 همین مرز را فراهم می‌کند.

Window را نباید فقط یک جعبه بصری روی صفحه دانست. در محیط گرافیکی، window معمولاً ناحیه‌ای قابل مشاهده است که سیستم‌عامل مدیریت می‌کند. اما در مدل CatalystUI، مفهوم گسترده‌تر است: window زمینه‌ای system-facing است که از طریق آن خروجی ارائه و interaction دریافت می‌شود.

### نمایی به درون System

Window مانند نمایی به system عمل می‌کند. نه system را می‌سازد و نه renderer را جایگزین می‌کند. بلکه زمینه boundedای فراهم می‌کند که خروجی renderer بتواند به تحویل system-level متصل شود. این مرز ممکن است شامل موقعیت، اندازه، focus، visibility، device context، output channel یا هر نوع scope تعریف‌شده توسط system باشد.

در رابط‌های بصری، تشخیص این نقش آسان است چون window می‌تواند با ناحیه مستطیلی روی display متناظر باشد. در دامنه‌های دیگر، همین نقش ممکن است توسط نشست خط فرمان، زمینه خروجی صوتی، کانال دستگاه، viewport مجازی یا سازوکار دیگری ایفا شود.

### دریافت Interaction

Window فقط خروجی را حمل نمی‌کند؛ معمولاً interaction را نیز دریافت می‌کند. system ممکن است keyboard events، pointer events، touch events، focus changes، resize events یا سیگنال‌های دستگاه را به window بفرستد. Window سپس این اطلاعات را به Stack بالا می‌فرستد تا renderer، frame، graph و control مناسب بتوانند آن را پردازش کنند.

### وابستگی به پلتفرم

Window اغلب جایی است که تفاوت پلتفرم‌ها آشکار می‌شود. Windows، macOS، Linux، browser، console، embedded runtime و device-specific environmentها همگی روش‌های متفاوتی برای تعریف، ایجاد و مدیریت window دارند. CatalystUI این تفاوت‌ها را حذف نمی‌کند؛ آن‌ها را در جای درست خود قرار می‌دهد تا لایه‌های بالاتر مجبور نشوند همه جزئیات native را بدانند.

### مرز میان Renderer و System

Window پلی مفهومی میان renderer و system است. Renderer خروجی آماده می‌کند. System دستگاه‌ها و سرویس‌های واقعی را فراهم می‌کند. Window می‌گوید این خروجی در کدام زمینه system باید قرار گیرد و interactions از کدام زمینه باید وارد شوند.
