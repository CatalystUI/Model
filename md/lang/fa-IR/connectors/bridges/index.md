# 6.4 Connectors :: Bridge

## بحث عمیق

### از زمینه به Rendering

اتصال‌دهنده **Bridge** میان **Layer 4: Graphs & Frames** و **Layer 3: Renderers** قرار دارد. وظیفه آن حمل داده سازمان‌یافته interface از graph و frame به renderer است؛ جایی که آن داده می‌تواند تبدیل شدن به خروجی قابل ادراک را آغاز کند.

Layer 4 زمینه سازمان‌یافته را می‌شناسد: componentها کدام‌اند، چگونه به هم مربوط‌اند، چه boundsی دارند و interface فعال در کل چگونه باید فهمیده شود. Layer 3 مسئول rendering است. Bridge نقطه عبور میان این دو نگرانی است.

### چرا Bridge لازم است

Graph، frame و renderer یک زبان طبیعی مشترک ندارند. Graph روابط را سازمان می‌دهد. Frame زمینه فعال و bounds را تعریف می‌کند. Renderer خروجی تولید می‌کند. Bridge اجازه می‌دهد داده آماده‌شده بدون مخلوط شدن مسئولیت‌ها به renderer برسد.

در بسیاری از پیاده‌سازی‌ها، Bridge لازم نیست پیچیده یا پرزرق‌وبرق باشد. گاهی فقط داده frame را expose می‌کند، buffer یا command list را منتقل می‌کند، یا اجازه می‌دهد renderer به اطلاعات مورد نیاز دسترسی داشته باشد. اما از نظر مدل، همین نقطه عبور بسیار مهم است.

### حمل Frame به جلو

در جریان بالا به پایین، Bridge خروجی آماده Layer 4 را می‌گیرد و به Layer 3 می‌برد. این به معنای آن نیست که Bridge layout محاسبه می‌کند، componentها را سازمان می‌دهد یا خروجی را render می‌کند. آن مسئولیت‌ها برای لایه‌های اطراف است. Bridge در میانه قرار دارد تا آن مسئولیت‌ها جدا بمانند.

### تعامل در مسیر برگشتی

گاهی interaction نیز باید از renderer یا فضای خروجی به graph برگردد. برای نمونه، مختصات pointer ممکن است نیاز داشته باشد از فضای window یا render target به فضای interface تبدیل شود. Bridge می‌تواند اطلاعات لازم برای این عبور را فراهم کند یا مسیر بازگشت را برای Layer 4 روشن نگه دارد.

### Bridge یعنی اتصال، نه تصاحب

نام Bridge عمداً ساده است. این connector قرار نیست framework دیگری داخل framework باشد. قرار است gap میان زمینه سازمان‌یافته و rendering را پر کند. هرچه این مرز تمیزتر باشد، جایگزینی renderer، تغییر domain یا پشتیبانی از چند backend آسان‌تر می‌شود.
