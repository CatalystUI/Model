# 4.3 Domains :: Auditory

## Explicación en profundidad

Después del dominio visual, el dominio **auditivo** describe datos moldeados para la audición. Los datos auditivos son información pensada para percibirse mediante sonido: palabras habladas, música, alertas, tonos o cualquier otra salida que el usuario entiende escuchando. Mientras que los datos visuales organizan el significado en una forma legible por la vista, los datos auditivos organizan el significado en sonido basado en el tiempo.

Esto hace que el dominio auditivo sea diferente del dominio visual de una forma importante. La información visual a menudo puede explorarse de una sola vez, pero la información auditiva normalmente se despliega con el tiempo. Un usuario puede mirar una pantalla y reconocer de inmediato varias relaciones, pero un sonido debe escucharse en secuencia. Por eso, los datos auditivos dependen mucho del tiempo, el orden, la duración y el ritmo. El significado no está solo en lo que se oye, sino en cuándo se oye y cómo cambia.

Un archivo de audio almacenado no es auditivo solo porque contiene datos de sonido. Mientras permanece almacenado, codificado o representado de forma abstracta, sigue siendo simbólico. Se vuelve auditivo cuando el sistema lo produce como sonido perceptible. Lo mismo ocurre con texto escrito leído en voz alta por un lector de pantalla, una notificación traducida en un timbre o un evento de juego expresado mediante música. En cada caso, el sistema ha tomado información y la ha asignado a la audición.

### Comprender los datos auditivos

Una forma útil de entender los datos auditivos es considerar **contenido**, **tiempo** y **tono**. No son categorías formales del modelo, pero ayudan a explicar cómo el sonido transporta significado de forma distinta a la vista.

**Contenido** describe qué comunica el sonido. En una salida hablada, pueden ser las palabras que se están leyendo. En la música, puede ser melodía, armonía o progresión. En una notificación, puede ser el patrón reconocible que le dice al usuario que algo ha ocurrido. El contenido auditivo es la sustancia de lo que se espera que el usuario oiga y entienda.

**Tiempo** describe cuándo ocurre el sonido y cuánto dura. Un tono de advertencia reproducido demasiado tarde puede perder su utilidad. Un mensaje hablado que avanza demasiado rápido puede volverse difícil de seguir. La música que responde de inmediato a una acción del usuario puede sentirse conectada, mientras que el sonido retrasado puede hacer que el sistema se sienta desconectado. El tiempo importa porque los datos auditivos se experimentan en movimiento.

**Tono** describe la calidad o el carácter del sonido. Un timbre suave, un pitido agudo y una voz hablada tranquila pueden comunicar significados muy diferentes aunque todos sean señales auditivas breves. El tono ayuda al usuario a entender urgencia, estado de ánimo, confirmación, advertencia o finalización. Da al sonido su carácter emocional y práctico.

### Significado auditivo

La salida auditiva expresa significado mediante sonido, pero el sonido en sí no debe confundirse con todo el significado. Un pitido de advertencia puede comunicar un problema, pero el pitido no es el problema. Una etiqueta hablada puede comunicar texto, pero la voz no es la estructura subyacente. Una señal musical puede comunicar éxito, peligro o transición, pero el significado viene de cómo el sistema usa esa señal dentro de la experiencia.

Esta distinción importa porque el sonido puede ser potente sin ser preciso. Un tono breve puede captar la atención del usuario, pero puede no explicar qué ocurrió. Un mensaje hablado puede explicar con claridad, pero puede tardar más que una señal visual. La música puede moldear la sensación de una experiencia, pero puede no comunicar instrucciones exactas. El diseño auditivo es más fuerte cuando el sonido coincide con el tipo de significado que el sistema necesita expresar.

Los datos auditivos también afectan al usuario de forma distinta a los datos visuales porque el sonido puede llegar al usuario sin exigirle mirar directamente al sistema. Un temporizador puede sonar desde otra habitación. Una aplicación de navegación puede hablar mientras los ojos del usuario permanecen en la carretera. Un lector de pantalla puede permitir que un usuario use software sin depender de la vista. Esto hace que el dominio auditivo sea especialmente valioso cuando la atención está dividida, la visión no está disponible o el sonido es el camino más claro para la comunicación.

### Datos auditivos y accesibilidad

El dominio auditivo es central para la accesibilidad porque puede transportar información que de otro modo podría quedar atrapada visualmente. El texto puede hablarse. El estado de la interfaz puede anunciarse. La navegación puede guiarse mediante sonido. Para algunos usuarios, la salida auditiva no es una mejora; es la forma principal en que el sistema se vuelve usable.

Al mismo tiempo, la información auditiva también puede crear problemas de accesibilidad cuando es la única forma en que se comunica el significado. Una advertencia que existe solo como sonido puede ser pasada por alto por un usuario sordo o con dificultades auditivas. Una instrucción hablada puede ser difícil de seguir en un entorno ruidoso. Un efecto de sonido puede confirmar una acción, pero si no hay otra representación de esa confirmación, el significado pasa a depender solo de la audición.

Aquí es donde los dominios ayudan a revelar lo que el sistema realmente está haciendo. Si un significado importante se transporta solo mediante sonido, el desarrollador puede preguntar si también debería estar disponible de forma simbólica, visual, táctil o mediante otra forma. El objetivo no es debilitar el diseño auditivo, sino preservar el significado a través de las formas en que los usuarios realmente perciben el sistema.

### Datos auditivos en experiencias más amplias

Los datos auditivos suelen trabajar junto a otros dominios. En un reproductor de vídeo, el sonido puede transportar habla o música mientras las imágenes transportan movimiento. En un juego, el audio puede comunicar distancia, peligro, atmósfera o retroalimentación. En un sistema operativo, el sonido puede apoyar notificaciones, errores y confirmaciones. En cada caso, el dominio auditivo identifica la parte de la experiencia moldeada para la audición.

Cuando el sonido se integra con otras formas de percepción, puede convertirse en parte de un intercambio multisensorial más amplio. Un sonido emparejado con una animación visual puede hacer que una acción se sienta completa. Una dirección hablada emparejada con un mapa puede guiar al usuario con más claridad que cualquiera de las dos formas por separado. Una vibración emparejada con un tono de alerta puede hacer que una notificación sea más difícil de pasar por alto. La parte auditiva sigue teniendo su propio papel, pero la experiencia completa puede depender de cómo trabajan juntos los dominios.

En resumen, el dominio auditivo describe información moldeada en una salida audible. Ayuda a explicar cómo los sistemas usan el sonido para comunicar contenido, tiempo, tono y retroalimentación. Cuando los datos auditivos se manejan bien, el usuario puede oír lo que el sistema presenta, reconocer qué cambió y responder sin necesitar que cada parte de la experiencia sea visible.
