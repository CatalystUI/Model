# 2. Resumen

Para entender cómo funciona una interfaz de usuario, primero debemos definir “_el flujo de información_”. Todos los días, se den cuenta o no, las personas interactúan con sistemas de información: un smartphone, un ordenador o un sensor de puerta en una tienda (más sobre eso después). En cada sistema, se presenta información, el usuario la interpreta, responde opcionalmente, y después el sistema procesa esa respuesta. Luego el sistema vuelve a presentar información, y el ciclo se repite durante toda la interacción. El ciclo puede comenzar en cualquier punto: la información puede haberse presentado mucho antes de que el usuario pudiera interpretarla, o un usuario puede responder sin que se haya presentado información. Sin importar cuándo o cómo comience el flujo, se aplica el mismo ciclo.

El Modelo CatalystUI se construye alrededor de este flujo. Proporciona una estructura de alto nivel para describir cómo la información fluye entre un usuario y un sistema de información, incluso cuando el sistema no se parece a una interfaz de usuario tradicional. En otras palabras, un sensor de puerta de una tienda puede parecer que “detecta” a una persona casi mágicamente, pero el flujo de información hace que el proceso sea sencillo: el usuario ve la entrada, reconoce el camino hacia delante y entra en el área de detección. Ese movimiento se convierte en entrada para el sistema. El sistema lo procesa, abre la puerta como salida perceptible, y el usuario responde caminando a través de ella. Tras un breve retraso, el sistema cierra la puerta, terminando el intercambio hasta que otra acción reinicie el ciclo.

Junto con el flujo de información, una _interfaz de usuario_ define cómo ocurre ese flujo dentro de un sistema de información dado. Determina cómo el sistema acepta entradas, produce salidas y permite al usuario interactuar con él. Como cada sistema tiene necesidades distintas, con el tiempo se han desarrollado muchas formas diferentes de describir e implementar estas interacciones, incluidas las “interfaces humanas” (“HI”), las “interfaces hombre-máquina” (“HMI”) y las “interfaces humano-ordenador” (“HCI”). En la era moderna de la informática, la forma más familiar de estas interfaces es la “interfaz gráfica de usuario” (“GUI”).

Cuando comparamos las distintas implementaciones, empieza a aparecer un patrón común. A pesar de sus diferencias externas, podemos identificar tres conceptos que aparecen en todas las interfaces de usuario: 1) “dominios”, que categorizan y organizan datos; 2) “el stack”, que representa y explica datos; y 3) “connectors”, que transforman, modifican y traducen datos. Cada concepto es útil por separado, pero juntos forman un _sistema_ _reversible_ que puede describir tanto la interfaz completa como los procesos individuales. Aquí es donde se hace clara la fuerza del Modelo CatalystUI: al separar la interacción en categorización, representación y traducción, hace que los sistemas de información sean más fáciles de explicar, depurar y comprender.
