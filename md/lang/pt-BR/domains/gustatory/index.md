# 4.6 Domains :: Gustatory

## Discussão aprofundada

Depois do olfato, o domínio **gustativo** descreve dados moldados para o paladar. Dados gustativos são informações feitas para serem percebidas pela língua e pela boca, como doçura, amargor, salinidade, acidez, sabor umami ou outra sensação baseada no gosto. Enquanto dados visuais são vistos, dados auditivos são ouvidos, dados táteis são sentidos e dados olfativos são cheirados, dados gustativos são saboreados.

Esse domínio pode parecer distante do software cotidiano, mas essa distância é significativa. O paladar não é um método comum de saída para computadores, então há menos exemplos familiares para usar como referência. Mesmo assim, o modelo ainda deve levá-lo em conta. Se um sistema consegue comunicar intencionalmente por meio do paladar, então essa interação merece um lugar na mesma discussão que visão, som, tato e olfato.

Dados gustativos também ajudam a revelar como muitas suposições sobre interfaces se tornaram estreitas. Sistemas modernos muitas vezes esperam que o usuário receba informação por uma tela, com outros sentidos tratados como secundários ou incomuns. O paladar resiste a essa suposição. Ele nos lembra que a percepção humana é maior do que as formas de saída que os dispositivos atuais tendem a favorecer.

### Compreendendo dados gustativos

Uma forma útil de entender dados gustativos é considerar como um gosto chega ao usuário, com que clareza é percebido e quanto tempo permanece. Essas ideias podem ser descritas por **meio**, **intensidade** e **duração**. Novamente, essas não são categorias formais do modelo, mas ajudam a explicar como o gosto carrega significado na prática.

**Meio** descreve como um gosto é entregue. Um gosto pode vir por comida, líquido, material dissolvível, estimulação elétrica ou um dispositivo especializado projetado para saída baseada no paladar. O meio importa porque o paladar geralmente exige contato direto com a boca. O sistema deve considerar como o usuário recebe o sinal com segurança, intenção e conforto.

**Intensidade** descreve quão perceptível ou distinto é um gosto. Um sabor suave pode apoiar associação ou atmosfera, enquanto um mais forte pode comunicar uma mudança mais imediata. A intensidade deve ser tratada com cuidado porque o gosto pode rapidamente se tornar desagradável, distrativo ou fisicamente desconfortável. Um sinal gustativo precisa de clareza suficiente para ser reconhecido sem sobrecarregar o usuário.

**Duração** descreve quanto tempo um gosto permanece perceptível. Alguns gostos desaparecem rapidamente, enquanto outros persistem depois que a interação original terminou. Isso torna o tempo difícil porque o sinal pode continuar afetando o usuário depois que o sistema já avançou. Uma saída baseada no paladar deve ser projetada com todo o efeito posterior em mente, não apenas o momento em que é introduzida.

### Significado gustativo

A saída gustativa expressa significado por meio do gosto. Um gosto amargo pode sugerir aviso. Um gosto doce pode sugerir recompensa, conforto ou conclusão. Um gosto ácido pode sugerir intensidade, surpresa ou mudança. O gosto é a forma perceptível, enquanto o significado vem de como o sistema usa esse gosto dentro da experiência.

Isso torna o design gustativo altamente dependente de contexto. O paladar é pessoal, cultural, biológico e emocional. Um sabor que parece agradável para um usuário pode parecer distrativo ou desagradável para outro. O paladar também tem uma relação próxima com saúde, apetite, memória e conforto corporal, o que significa que deve ser usado com mais cuidado do que muitas outras formas de saída.

Dados gustativos são mais fortes quando o gosto é realmente relevante para a experiência representada. Um treinador nutricional, simulação médica, sistema de educação alimentar ou experiência gastronômica imersiva pode comunicar algo pelo paladar que visão e som só conseguem descrever indiretamente. Nessas situações, o gosto não é um efeito decorativo. É a forma mais direta da informação.

### Dados gustativos e acessibilidade

O domínio gustativo pode apoiar acessibilidade em situações especializadas, especialmente quando o gosto oferece outra forma de reconhecer uma condição, resposta ou ambiente. Ele pode ajudar em educação, terapia, treinamento ou simulação quando o gosto faz parte do que o usuário deve compreender. Nesses casos, a saída gustativa dá ao sistema outro caminho para tornar informação perceptível.

Ao mesmo tempo, a interação baseada no paladar carrega responsabilidade séria. Um sistema que usa gosto deve levar em conta alergias, sensibilidades, restrições alimentares, condições de saúde, consentimento, higiene e conforto pessoal. Um sinal gustativo não pode ser tratado como uma mudança de cor, efeito sonoro ou vibração. Ele entra no corpo, então a segurança e a agência do usuário devem permanecer centrais no design.

É aqui que os domínios ajudam a esclarecer a responsabilidade de design. Se o significado é carregado pelo paladar, o desenvolvedor pode perguntar se esse mesmo significado também deveria estar disponível simbolicamente, visualmente, auditivamente, tatilmente ou olfativamente. O propósito não é forçar o paladar nas interfaces, mas reconhecê-lo quando é relevante e preservar o significado quando ele não está disponível para todos os usuários.

### Dados gustativos em experiências mais amplas

Dados gustativos aparecerão com mais frequência como parte de uma experiência multissensorial mais ampla. Uma simulação alimentar pode combinar gosto com olfato, visão e som. Um treinador médico pode usar gosto para representar uma condição que importaria no mundo real. Um sistema terapêutico pode usar sabor junto com aroma ou toque para guiar memória, atenção ou conforto.

Nessas situações, o domínio gustativo identifica a parte da experiência feita para ser saboreada. Ele não precisa carregar a interface inteira sozinho. Sua força geralmente é específica, incorporada e contextual. O gosto pode comunicar qualidade, aviso, recompensa, realismo ou presença de formas que outros domínios podem apoiar, mas não substituir totalmente.

### Dados gustativos e o escopo do Modelo

A natureza incomum das interfaces gustativas é uma das razões mais claras para definir o domínio. Sem um modelo como CatalystUI, é fácil construir nossa compreensão de interfaces em torno dos dispositivos que já usamos: telas, alto-falantes, teclados, controles e touchscreens. Essas ferramentas são importantes, mas não são o limite da interação humano-computador.

Ao nomear o domínio gustativo, o CatalystUI mantém o modelo honesto. Ele não exige que todo sistema use paladar e não finge que computação baseada no gosto seja comum. Em vez disso, reconhece que o paladar é um caminho válido para percepção quando um sistema o usa intencionalmente para comunicar. Esse reconhecimento impede que o modelo se torne uma descrição de hábitos atuais em vez de uma descrição da própria interação.

Isso importa porque um usuário não é apenas um espectador de informação. Um usuário percebe por meio de um corpo. Alguns sistemas talvez precisem apenas de uma tela. Outros talvez precisem de som, toque, olfato, paladar ou uma combinação de vários domínios para comunicar fielmente. O CatalystUI dá aos desenvolvedores uma forma de discutir essas possibilidades sem tratá-las como exceções fora do modelo.

Em resumo, o domínio gustativo descreve informação moldada em saída baseada no paladar. Ele ajuda a explicar como sistemas podem usar **meio**, **intensidade** e **duração** para comunicar pelo gosto. Quando dados gustativos são relevantes e tratados com responsabilidade, eles podem tornar a informação diretamente perceptível pelo corpo, ao mesmo tempo em que nos lembram que o design de interfaces começa com a capacidade do usuário de perceber, não com as limitações dos dispositivos que estamos acostumados a construir.
