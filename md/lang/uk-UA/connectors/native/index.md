# 6.6 Connectors :: Native

## Докладне обговорення

### Від Windows до Systems

Connector **Native** стоїть між **Layer 2: Windows** і **Layer 1: Systems**. Він з’єднує window з underlying system, щоб вивід міг бути доставлений, а взаємодії могли бути прийняті через фактичне середовище, у якому працює програма.

Layer 2 дає Stack window: обмежене представлення, container або point of delivery. Layer 1 дає Stack system: операційне середовище, доступ до апаратури, сервіси, пристрої і native behavior, які роблять window можливою. Connector Native є точкою переходу між ними.

Саме тут Stack найпряміше торкається практичної реальності обчислень. Window не існує лише в уяві. Щось має попросити system створити її, налаштувати, підтримувати, оновлювати і повідомляти через неї про взаємодії. Цим «чимось» є connector Native.

### Визначення Bindings

**binding** — це кероване з’єднання між одним layer і функціональністю, наданою іншим. У connector Native bindings відкривають поведінку system для window у формі, яку програма може використовувати, не змушуючи window ставати самою system.

Native binding може відкрити можливість створити window, змінити її заголовок, отримати введення з клавіатури, відреагувати на рух pointer, змінити розмір активної області, запросити focus, звернутися до device або зв’язатися із system service. Details залежать від system і реалізації, але ідея та сама: binding дає придатне з’єднання з native functionality.

Bindings важливі тому, що system може мати потужні можливості, які не стають автоматично доступними мові або структурі, використаним рештою Stack. Connector Native збирає, формує і використовує ці з’єднання.

### Надання Native Access

У багатьох реалізаціях connector Native переважно надає bindings до низькорівневої функціональності system. Це може здаватися звичним, бо розробники знають native APIs, platform libraries, виклики операційної системи та інтерфейси пристроїв. Але в Stack це не випадкові деталі реалізації, а засіб, через який Layer 2 отримує доступ до Layer 1.

Графічній window може знадобитися binding до platform windowing API. Інтерфейсу командного рядка може знадобитися binding до введення і виведення terminal. Спеціалізованому device можуть знадобитися bindings до кнопок, sensors, speakers, lights або інших пристроїв, якими керує system.

Важлива не конкретна platform, а те, що window не може доставляти вивід або приймати взаємодію без способу спілкуватися із system, яка її містить.

### Більше ніж Wrapper

Connector Native легко назвати wrapper навколо system APIs, бо він часто відкриває native behavior. Але wrapper описує стиль реалізації, а binding описує те, що connector насправді надає.

Native — не просто набір platform calls під window. Це формальне відношення між window і system. Він визначає, як window отримує існування, підтримане system, як поведінка system стає доступною Stack і як взаємодії, що виникли в system, починають рухатися вгору.

Модель не намагається лише повторити історичні терміни розробників. Вона описує сам процес: connector Native важливий тому, що зв’язує Layer 2 з Layer 1.

### Створення й підтримання Window

У низхідному потоці connector Native дозволяє window працювати через system. Window може знадобитися створити, показати, приховати, змінити розмір, перемістити, сфокусувати, оновити або закрити. Ці дії потребують відношення із system, бо саме system надає середовище, у якому вони можуть відбуватися.

Connector Native відкриває bindings, потрібні для цих дій. Через нього Layer 2 може запросити поведінку system, не забираючи на себе всю відповідальність за керування system. Window лишається обмеженою точкою доставки; system лишається середовищем, що надає нижчу функціональність.

Це важливо, бо systems різняться. Різні операційні системи, devices, runtimes і environments надають різні APIs та поведінку. Connector Native дає Stack місце для представлення цих відмінностей, не змушуючи решту Моделі ставати залежною від конкретної system.

### Отримання Interactions

Оскільки Stack зворотний, connector Native є першим явним connector, який бере участь у момент, коли взаємодія входить із system.

Натискання клавіші, рух pointer, дотик, дія controller, сигнал device, зміна розміру, зміна focus або інша подія, що виникла в system, має перейти з Layer 1 до Layer 2. Connector Native приймає або відкриває відомості про системну взаємодію і переносить їх у window.

Звідти взаємодія може продовжити рух угору через Surface до Renderers, потім через Bridge, Adapter, Parser і Data за потреби. Connector Native зазвичай не вирішує, що означає взаємодія. Він зв’язує джерело взаємодії в system зі шляхом взаємодії у window.

Так нижня межа лишається чистою: system не мусить розуміти верхні layers, а верхні layers не повинні поводитися так, ніби вони самі є system.

### Збереження Boundary

Connector Native має зберігати межу між window і system. Він відкриває потрібну функціональність system, але не стирає відмінність між двома layers.

Binding дає доступ без тотожності. Window може використовувати функціональність system, не стаючи system. System може надавати поведінку, не стаючи window. Connector визначає відношення між ними.

Ця межа дозволяє CatalystUI послідовно описувати window у різних середовищах. Одна system може надати desktop window, інша — terminal, ще інша — канал виводу конкретного device, а ще інша — remote або virtualized environment. Native bindings різняться, але роль connector лишається тією самою.

### Чому Connector важливий

Connector Native не дозволяє Stack плутати window із system, яка її надає. Без нього Windows мусив би напряму містити поведінку, залежну від system, або Systems мусив би розуміти високорівневе поняття window.

Windows лишається відповідальним за обмежений контекст, через який проходять вивід і взаємодія. Systems лишається відповідальним за нижнє середовище, сервіси, devices і native behavior. Connector Native відповідає за binding між ними.

Це останній явний connector Stack. Тут змодельований інтерфейс досягає system під собою. Він може виглядати як platform access і бути реалізований через native libraries, виклики операційної системи, device APIs або runtime services. Але його призначення простіше: надати bindings.

Connector Native зв’язує window із system, дозволяючи виводу покинути Stack, а взаємодії ввійти в нього. Так він завершує явний шлях між змодельованим інтерфейсом і реальною середою, у якій цей інтерфейс має жити.
