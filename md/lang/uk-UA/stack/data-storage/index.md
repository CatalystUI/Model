# 5.1 The Stack :: Data Storage

## Докладне обговорення

### Імпліцитна межа

**Data Storage** — це імпліцитна верхня межа Stack. Вона представляє умову, за якої вміст, стан або ресурс залишаються доступними до того, як явні шари почнуть із ними працювати, а також місце, де результат взаємодії може бути збережений пізніше. Модель потребує цієї межі, бо інтерфейс не створює весь свій предмет із нічого. Щось має бути доступним для читання, отримання, приймання або посилання, перш ніж його можна буде інтерпретувати, перетворити, відрендерити або використати як основу для дії.

Data Storage є імпліцитним, бо Stack не моделює внутрішню механіку самого зберігання. Модель може залежати від збереженого ресурсу, але їй не потрібно описувати кожну деталь того, як цей ресурс утримується. Ці питання належать навколишній інформаційній системі. Stack починається тоді, коли певна форма вмісту стає частиною активного потоку інтерфейсу.

### Збережена доступність і активне представлення

Відмінність між Data Storage і Layer 7: **Digital Data** — це відмінність між **збереженою доступністю** і **активним представленням**. Data Storage описує місце або умову, у яких щось може зберігатися. Digital Data описує першу явну форму цього чогось після того, як воно входить у змодельований процес як представлення, читабельне для комп’ютера.

Наприклад, документ може існувати у файловій системі, запис може існувати в базі даних, а відповідь може чекати за API. Поки він залишається лише доступним для звернення, він належить до Data Storage. Коли інтерфейс читає цей документ, отримує цей запис, відкриває цю відповідь або інакше вводить ресурс в активний потік, він стає Layer 7. Важлива зміна не в тому, що вміст раптом став осмисленим. Важлива зміна в тому, що тепер він представлений усередині Stack.

### Постійність і перетворення

Data Storage стосується постійності й доступності. Явний Stack стосується перетворення. Коли збережений ресурс стає Digital Data, Модель може почати описувати, що з ним відбувається: як його інтерпретує Structure & Semantics, як його формують у Components, Controls, & Layouts, як його організовують через Graphs & Frames, як його готує Renderer, як його доставляють через Window і як System переносить його до Human Interface.

Це розділення важливе, бо зберігання й перетворення відповідають на різні запитання. Data Storage запитує, чи може щось залишатися доступним у часі. Digital Data запитує, з яким активним двійковим, текстовим, потоковим або отриманим представленням інтерфейс працює зараз. Перше пояснює утримання. Друге починає змодельований потік.

### Межа джерела й повернення

У потоці згори вниз Data Storage служить межею джерела. Збережений ресурс вибирається або отримується, а потім входить у Stack як Digital Data. Від цього моменту Модель може простежити, як ресурс розуміється, розміщується, перетворюється і доставляється користувачеві. Сам Data Storage не рендерить, не розбирає, не розкладає і не інтерпретує ресурс. Він лише надає умову, з якої може початися активне представлення.

У потоці знизу вгору Data Storage служить межею повернення. Взаємодія користувача може запросити, створити, оновити, видалити або інакше вплинути на щось у потоці інтерфейсу. Отримана зміна може пройти вгору через Stack, доки знову не стане Digital Data. Якщо цей результат має залишатися доступним за межами безпосереднього процесу, він повертається в Data Storage як збережений стан. Stack не потрібно моделювати кожну стратегію запису, транзакцію бази даних, оновлення кешу або крок мережевої синхронізації, щоб розпізнати, що результат повернувся до постійності.

### Приклади в контексті

Саме тому Data Storage може проявлятися через багато технологій, не визначаючись жодною з них. Файлова система, база даних MySQL, колекція MongoDB, сервіс на основі API, хмарне об’єктне сховище, область пам’яті пристрою або потоковий сервіс можуть служити Data Storage, коли надають утриману доступність поза активним Stack. Коли конкретний файл, запис, відповідь, buffer або stream вводиться в потік інтерфейсу, Модель розглядає це активне представлення як Digital Data.

### Чому розділення важливе

Відокремлення Data Storage від Layer 7 зберігає Stack чистим. Без цієї відмінності Модель змішувала б місце, де щось утримується, з формою, яку воно набуває, коли інтерфейс починає з ним працювати. Це зробило б Digital Data відповідальними і за постійність, і за активне представлення, послаблюючи призначення явних шарів.

Зберігаючи Data Storage імпліцитним, Модель утримує чітку межу: зберігання оточує потік інтерфейсу, а Digital Data починає його. Це дозволяє Stack описувати перетворення конкретного активного представлення, не заплутуючись у кожному можливому механізмі зберігання за ним. Data Storage пояснює, звідки може прийти утриманий вміст і куди можуть повернутися збережені результати; Layer 7 починає явний процес перетворення цього вмісту на щось, що інтерфейс може зрозуміти, перетворити і зрештою представити.
