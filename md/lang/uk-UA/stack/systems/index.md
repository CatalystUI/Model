# 5.8 The Stack :: Systems

## Докладне обговорення

### Найнижчий явний шар

**Systems** — це найнижчий явний шар Stack. Цей шар представляє обчислювальне середовище, яке надає базові сервіси, пристрої та операції, потрібні для доставки output і отримання interaction. Там, де Layer 2 визначає обмежений контекст, через який проходять output і interaction, Layer 1 представляє ширше середовище, що робить цей контекст можливим.

System не слід розуміти лише як настільну операційну систему. У Моделі CatalystUI system — це організований набір процесів і можливостей платформи, який підтримує інтерфейс під час runtime. Це може бути традиційна операційна система, embedded environment, console, browser runtime, hardware platform або інший managed computing context. Визначальна ознака — не категорія продукту. Визначальна ознака в тому, що system надає lower-level capabilities, через які інтерфейс справді може працювати.

### Операційне середовище

Шар System надає навколишнє середовище виконання для явного Stack. Він може керувати hardware access, input devices, output devices, drivers, permissions, scheduling, memory, files, processes, windows, channels або іншими platform-level services. Ці деталі сильно відрізняються між реалізаціями, але всі вони виконують одну концептуальну роль: дозволяють інтерфейсу з’єднуватися з реальними можливостями машини або інформаційної системи.

Це відрізняє Layer 1 від Layer 2. Window — це обмежений system-facing контекст, який використовує інтерфейс. System — це ширше середовище, яке створює, володіє, розпізнає, обмежує й обслуговує цей контекст. Window надає конкретну точку з’єднання; system надає світ, у якому це з’єднання існує.

Тому шар System не є просто пасивною основою. Він активно бере участь у циклі інтерфейсу. Він доставляє відрендерений output до фізичних або логічних пристроїв, отримує input від цих пристроїв, застосовує правила платформи і розкриває операції, на які спираються верхні шари. Stack може описувати потік інтерфейсу, але system надає операційний ґрунт під цим потоком.

### Відношення до Windows

Systems і Windows тісно пов’язані, але це не один і той самий шар. Window отримує відрендерений output від Layer 3 і надає обмежений delivery context. System отримує цей windowed output і виконує нижчерівневу роботу, потрібну для доставки через доступні пристрої або сервіси.

У потоці згори вниз window передає output у system. System потім обробляє фактичний шлях доставки: надсилає visual output до дисплея, audio output до звукового пристрою, tactile output до haptic device, text output до terminal або іншу форму output до відповідного channel. Window визначає, де output належить; system переносить його в середовище, здатне зробити його сприйманим.

У потоці знизу вгору system отримує або виявляє interaction з людського боку інтерфейсу. Це може відбуватися через keyboard, pointer, touchscreen, microphone, controller, sensor, button або інший input path. System перетворює цю фізичну або device-level активність на system-level signal, який може бути пов’язаний із window і переданий угору через Stack.

### Доставка output

Шар System — це останній явний етап потоку згори вниз. До моменту, коли output досягає Layer 1, верхні шари вже інтерпретували початкове представлення, сформували придатні об’єкти інтерфейсу, організували їх у поточний операційний контекст, відрендерили цей контекст в output-ready форму і передали його через window. Тепер system виконує platform-level work, потрібну для того, щоб зробити цей output доступним Human Interface.

Це не означає, що сам system дорівнює сприйняттю користувача. Користувач не сприймає операційну систему напряму. Користувач сприймає фізичний або сенсорний результат, доступний через пристрої й канали, якими керує system. Тому Layer 1 залишається всередині процесу на боці комп’ютера, а імпліцитний Human Interface перебуває за ним як отримувач output.

Ця відмінність зберігає точність Моделі. System може створити світло через дисплей, звук через динаміки, вібрацію через мотор або інший сприйманий результат через пристрій чи сервіс. System надає останній явний механізм доставки; Human Interface отримує і сприймає результат.

### Походження interaction

Шар System також є першим явним етапом потоку знизу вгору. Користувач виконує дію поза явним Stack, але system — це місце, де ця дія стає доступною змодельованому інтерфейсу як interaction input. Сама людська дія належить імпліцитному Human Interface. System отримує ефект цієї дії через підтримуваний input path і починає перетворювати його на щось, що Stack може обробити.

Ось чому system тісно пов’язаний із interaction. Фізичне натискання клавіші, рух вказівника, touch gesture, spoken input, controller signal або sensor change спершу мають бути отримані обчислювальним середовищем, перш ніж верхні шари інтерфейсу зможуть відповісти. System зазвичай не визначає остаточний зміст цієї interaction. Він визначає, що щось сталося, надає релевантний device або platform context і передає interaction до відповідного window.

Звідти interaction може рухатися вгору через Stack. Window пов’язує її з обмеженим контекстом, renderer може допомогти перекласти або зіставити її, graph і frame можуть маршрутизувати її, а відповідний control нарешті може її обробити. System починає явний зворотний шлях, але зміст дії розв’язується вище в Stack.

### Правила й обмеження платформи

Systems важливі, бо кожен інтерфейс працює в межах обмежень. System може визначати, які пристрої доступні, як створюються windows, як доставляється input, як надаються permissions, як поводяться output channels, до яких resources можна отримати доступ і які operations підтримуються. Ці обмеження формують те, що може робити решта Stack.

Однак CatalystUI відокремлює ці platform concerns від верхньої моделі інтерфейсу. Components не мають напряму розуміти кожен driver або правило operating system. Renderers не мають керувати кожною hardware detail. Windows не мають представляти всю платформу. Layer 1 надає чітке місце для system-level behavior, дозволяючи верхнім шарам залишатися зосередженими на інтерпретації, придатності, організації й перетворенні.

Це розділення також дозволяє Моделі застосовуватися в різних середовищах. Desktop application, mobile app, embedded device, browser-based interface, command-line tool або specialized hardware system можуть мати різні platform rules, але кожен усе одно потребує шару system, що надає операційне середовище під інтерфейсом.

### Відношення до Human Interface

Systems розташовані прямо над імпліцитним **Human Interface**. Це означає, що Layer 1 — останній явний шар перед тим, як output залишає змодельований потік на боці комп’ютера, і перший явний шар після того, як дія користувача входить у нього. Тому system — це межа між керованим обчислювальним середовищем і людиною, яка сприймає й діє.

Ця межа суттєва. Модель може описувати, як system надсилає output до пристрою, але не моделює напряму сенсорний досвід користувача, біологію, увагу, емоції або інтерпретацію. Так само Модель може описувати, як system отримує input signal, але не моделює напряму повний людський процес, що породив дію. Ці питання належать імпліцитному Human Interface.

Розміщуючи Systems на Layer 1, Stack чітко визначає найнижчу явну точку, де процес на боці комп’ютера можна описати перед переходом до людського сприйняття і дії.

### Чому шар важливий

Systems утримує Stack у реальній роботі. Без цього шару Модель описувала б rendering і windows так, ніби доставка output і отримання input відбуваються автоматично. На практиці кожен інтерфейс залежить від базового середовища, яке керує пристроями, resources, permissions, execution і platform behavior.

Відокремлюючи Systems від Windows і Human Interface, Модель зберігає чисту фінальну межу. Windows надає обмежений контекст для output і interaction. Systems надає базове операційне середовище, яке доставляє output і отримує input. Human Interface сприймає output і створює action. Ця відмінність дозволяє CatalystUI описувати інтерфейси на різних платформах і в різних доменах, не зводячи system до однієї operating system, конкретного device або visual display model.
