# 5.9 The Stack :: Human Interface

## Докладне обговорення

### Імпліцитна людська межа

**Human Interface** — це імпліцитна нижня межа Stack. Він представляє користувача: людину, яка отримує сприйманий output від system і створює дії, що можуть стати interaction input. Простіше кажучи, цей шар — це ви.

Це може звучати очевидно, але важливо. Stack існує, щоб описувати процес комунікації між користувачем та інформаційною системою. Якщо Data Storage пояснює межу, де утриманий вміст може входити в активний потік або виходити з нього, Human Interface пояснює протилежну межу: місце, де computer output нарешті стає частиною людського досвіду і де людська дія починає зворотний шлях у system.

Human Interface імпліцитний, бо Модель не представляє напряму тіло, розум, увагу, емоції, чуття, наміри, спогади або вибір користувача. CatalystUI може описати, як system доставляє output до користувача і як дія користувача стає interaction input, але не вдає, що моделює всю людину. Це було б трохи амбітно. І ще моторошно. Stack потужний, але йому не потрібно ставати підручником психології з прикрученим renderer.

### Отримувач сприйманого output

У потоці згори вниз Human Interface — отримувач сприйманого output. Digital Data рухаються через явний Stack, стають інтерпретованими, сформованими, організованими, відрендереними, доставленими через window і перенесеними system, доки нарешті не можуть бути сприйняті. Коли цей output досягає чуттів користувача, явний Stack завершив свій низхідний шлях.

Це не означає, що користувач отримує Digital Data напряму. Людина природно не сприймає одиниці й нулі, memory buffers, draw calls, audio samples або system events. Користувач сприймає результат роботи system: світло, звук, вібрацію, рух, текст, просторову зміну або іншу форму сенсорного output. Human Interface — це місце, де output перестає бути просто доставленим і починає переживатися.

Ця відмінність зберігає чесність Моделі. System може надати output, але не може змусити зрозуміти. Дисплей може показати кнопку, динамік може відтворити звук, а пристрій може завібрувати, але користувач усе одно має сприйняти й інтерпретувати цей результат як людина. Модель визнає цю межу, не намагаючись визначити кожен особистий, біологічний або контекстний чинник. Іншими словами: CatalystUI може довести output до людини. Він не може змусити людину перестати ігнорувати сповіщення. На жаль.

### Джерело interaction

У потоці знизу вгору Human Interface — джерело дії. Користувач бачить, чує, відчуває, розуміє, реагує, вирішує і потім щось робить. Ця дія може бути натисканням клавіші, рухом вказівника, дотиком до екрана, вимовленням команди, поворотом ручки, проходом через поле сенсора або іншою поведінкою, яку system може отримати.

Сама дія починається поза явним Stack. Модель не описує напряму повний внутрішній процес, який привів користувача до дії. Вона починає моделювати зворотний шлях лише тоді, коли system отримує ефект цієї дії. У цей момент дія стає interaction input і входить у Layer 1: Systems, де може бути передана вгору через Stack.

Це зберігає ясну відмінність між **human action** і **system interaction**. Human action — це те, що робить користувач. Interaction input — це те, що system отримує від цієї дії. Вони тісно пов’язані, але не тотожні. Людина може намірятися натиснути одне, а випадково натиснути інше, або зачепити клавішу, тягнучись за чимось іще. System може отримати обидві події, але лише одна з них, ймовірно, буде осмисленим вираженням наміру користувача. Якщо тільки випадковий input не був метою; у такому разі вітаємо: інтерфейс увійшов у дуже експериментальну фазу.

### Чому шар імпліцитний

Human Interface імпліцитний з тієї самої причини, що й Data Storage: він потрібен потоку, але не моделюється напряму як явний шар перетворення. Stack залежить від користувача, але не перетворює користувача. Він не розбирає користувача, не рендерить користувача, не адаптує користувача і не зберігає користувача як component. Імовірно, так і краще.

Натомість Модель розглядає Human Interface як живу межу навколо нижнього кінця system. Явний Stack може описувати, як output готується і доставляється, і може описувати, як отримана interaction рухається вгору. Він зупиняється до того, як заявити права на сам людський досвід.

Ця межа особливо важлива, бо користувач — не просто ще один пристрій. Дисплей надає visual output. Клавіатура надає input signals. Користувач сприймає, інтерпретує, вибирає, відповідає, помиляється в розумінні, вчиться, вагається, робить помилки і часом із повною впевненістю натискає не ту кнопку. Модель має поважати цю відмінність. Тому Human Interface присутній, бо Stack побудовано для людської комунікації, але він імпліцитний, бо людина не є частиною процесу перетворення на боці машини.

### Сприйняття і намір

Human Interface завершує комунікаційний цикл, поєднуючи сприйняття і намір. В одному напрямку system надає щось сприймане. В іншому користувач відповідає дією. Це створює розмовний цикл у центрі CatalystUI: system говорить через output, користувач відповідає через interaction, а system обробляє цю відповідь, щоб продовжити обмін.

Саме тому Human Interface не можна звести до input devices. Keyboard, mouse, touchscreen, microphone, camera або controller можуть допомагати захоплювати interaction, але жоден із них не є користувачем. Це доступні system шляхи, через які дія користувача може ввійти в Stack. Human Interface — це людина, чиє сприйняття і намір надають цим сигналам значення.

Те саме стосується output devices. Monitor, speaker, haptic motor або інший output device може переносити сприймані дані, але пристрій не завершує досвід. Досвід завершується, коли користувач сприймає результат. Екран, повний ідеально відрендерених pixels, усе ще не є успішним інтерфейсом, якщо користувач не може побачити, зрозуміти, дістатися, почути, відчути або використати те, що було надано.

### Відношення до Systems

Human Interface розташований прямо під **Layer 1: Systems**. Шар System надає останню явну обробку output на боці комп’ютера і першу явну обробку interaction на боці комп’ютера. Human Interface перебуває за цим шаром як отримувач output від system і джерело дії користувача.

Це відношення визначає нижній край Stack. У потоці згори вниз system доставляє output до користувача. У потоці знизу вгору system отримує ефект дії користувача. Тому system — останній явний шар машинної операції, а Human Interface — імпліцитна межа, де машинна операція зустрічає людський досвід.

Розділяючи ці шари, Модель уникає змішування поведінки пристрою з досвідом користувача. System може знати, що клавішу було натиснуто, вказівник зсунувся або звук було відтворено. Він не знає автоматично, що користувач зрозумів, мав намір, відчув або помітив. Ці людські реальності перебувають за межами явного Stack, навіть якщо Stack існує, щоб їм служити.

### Доступність і людська різноманітність

Human Interface також нагадує Моделі, що користувачі — не взаємозамінні машини. Люди сприймають і діють через різні здібності, чуття, контексти, інструменти, обмеження, вподобання й середовища. Один користувач може переважно покладатися на visual output. Інший може залежати від auditory output, tactile feedback, keyboard navigation, screen readers, captions, simplified motion, alternate input devices або інших форм доступу.

Це не змінює структуру Stack. Це прояснює, чому Stack важливий. Розділяючи шари, CatalystUI може краще визначити, де відбувається збій, коли output доставлено, але він не є осмислено сприйманим, або коли користувач має намір, але не має придатного шляху його виразити. Межа Human Interface зберігає видимою мету всього потоку: system не просто створює output; він спілкується з людиною.

Ця людина може бути втомленою, розсіяною, блискучою, розгубленою, мати інвалідність, навчатися, робити кілька справ одночасно або намагатися закінчити щось за п’ять хвилин до дедлайну. Інтерфейс усе одно має зустріти її як людину. Бажано без вимоги спершу прочитати сорокасторінкове повідомлення про помилку.

### Чому шар важливий

Human Interface не дає Stack закінчитися на машині. Без цього імпліцитного шару Модель зупинилася б на system output і system input, ніби мета інтерфейсу — просто переміщати сигнали через hardware. Це пропустило б суть. Мета Stack не лише в тому, щоб створити output; вона в тому, щоб зробити можливою комунікацію між інформаційною системою і користувачем.

Відокремлюючи Human Interface від Systems, Модель зберігає чисту фінальну межу. Systems доставляє output і отримує input. Human Interface сприймає output і створює action. Явний Stack описує машинний процес між цими двома напрямками, а імпліцитний Human Interface нагадує, заради кого цей процес існує.

Саме тому Human Interface належить до Stack, навіть якщо його не пронумеровано. Користувач — не шар, який потрібно реалізувати, відрендерити, розібрати або покрити unit tests. Користувач — причина, з якої шари існують. І, якщо припустити, що користувач є людиною, Модель працює чудово.
