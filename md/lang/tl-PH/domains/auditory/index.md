# 4.3 Domains :: Auditory

## In-Depth Discussion

Ang **auditory** domain ay naglalarawan ng data na hinubog upang marinig. Kasama rito ang salita, musika, alert sounds, tones, sound effects, voice prompts, at anumang output na nauunawaan ng user sa pakikinig.

### Understanding Auditory Data

Iba ang auditory data sa visual data dahil karaniwang lumalabas ito sa paglipas ng panahon. Ang isang screen ay maaaring tingnan nang sabay-sabay, ngunit ang tunog ay kailangang marinig sa pagkakasunod-sunod. Dahil dito, mahalaga ang timing, rhythm, duration, volume, pitch, at order.

### Auditory Meaning

Ang meaning ng auditory data ay nasa tunog mismo at sa konteksto nito. Ang parehong beep ay maaaring notification, error, confirmation, o warning depende sa system. Ang spoken text naman ay maaaring direktang representasyon ng symbolic content, ngunit ang tono, bilis, at emphasis ay maaaring magdagdag ng dagdag na kahulugan.

### Auditory Data and Accessibility

Napakahalaga ng auditory domain sa accessibility, lalo na kapag kailangang isalin ang visual o symbolic data sa speech. Kasabay nito, hindi lahat ng user ay nakakarinig nang pareho, kaya mahalaga rin ang captions, visual indicators, tactile feedback, o iba pang alternatibong output.

### Auditory Data in Broader Experiences

Sa maraming modernong system, hindi nag-iisa ang auditory data. Maaari itong samahan ng visual changes, haptics, o other cues. Sa Model, ang domain na ito ay tumutulong tukuyin kung aling bahagi ng experience ang ipinapasa sa user sa pamamagitan ng pandinig.
