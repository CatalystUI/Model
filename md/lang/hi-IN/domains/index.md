# 4. Domains

## High-Level Overview

CatalystUI Model को describe करने के लिए हमें पहले domains से शुरू करना होगा। _domain_ उस data category को describe करता है जिसे interaction के दौरान handle किया जा रहा है। यह information flow को तोड़कर समझने का पहला step है। यह पहचानता है कि system किस _kind_ की information के साथ काम कर रहा है। दुकान के दरवाज़े का sensor movement detect करने के लिए visual या spatial cues का उपयोग कर सकता है। game controller haptic feedback पैदा करने के लिए tactile information का उपयोग कर सकता है। smart speaker speech process करते समय auditory information के साथ काम कर सकता है। लगभग सभी cases में domains इस बात से मिलते हैं कि लोग दुनिया को कैसे sense करते हैं। Model उस data को भी account करता है जो किसी specific sense तक पहुँचने से पहले होता है, और उस data को भी जो एक साथ कई senses में फैला होता है। इसलिए सात domains को “symbolic,” “visual,” “auditory,” “tactile,” “olfactory,” “gustatory,” और “multisensory” के रूप में define किया जाता है।

Domains उपयोगी हैं क्योंकि वे information flow को पहचानना, diagnose करना, और user की needs के आसपास shape करना आसान बनाते हैं। information किस domain से संबंधित है, यह पहचानकर हम साफ़ देख सकते हैं कि system क्या कर रहा है, क्या नहीं कर रहा है, और user experience के कौन-से हिस्से missing हो सकते हैं। accessibility के लिए यह विशेष रूप से महत्वपूर्ण है: यदि interface केवल visually communicate करता है, तो Model हमें यह पहचानने में मदद करता है कि tactile, auditory, या अन्य forms of information पर भी विचार करने की आवश्यकता हो सकती है। क्योंकि domains describe करते हैं कि information user के experience में कैसे participate करती है, data को domain में classify करने की शुरुआत इस question से होनी चाहिए कि interaction में उसका role क्या है। यदि data देखे जाने के लिए है, वह visual है; यदि सुने जाने के लिए है, वह auditory है; यदि महसूस किए जाने के लिए है, वह tactile है। यदि data अभी किसी specific sense से जुड़ा नहीं है, जैसे text file में होता है, वह symbolic है। यदि कई sensory categories मिलकर एक experience के रूप में काम करती हैं, जैसे video game जो visuals, sound, और controller vibration को जोड़ता है, वह multisensory है।

## Model में Domains की भूमिका

एक बार data को domain में classify कर दिया जाए, interaction के पास अधिक स्पष्ट starting point होता है। हम जानते हैं कि system कौन-सी information handle करता है, user को कैसा experience मिलेगा, और क्या communication के अन्य forms पर विचार करना चाहिए। उस category के स्थापित होने पर, Model data के type की पहचान से आगे बढ़कर यह describe कर सकता है कि वह interface के भीतर कैसे move करता है।
