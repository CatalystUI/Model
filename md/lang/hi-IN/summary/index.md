# 2. सारांश

यह समझने के लिए कि user interface कैसे काम करता है, हमें पहले “_information flow_” को परिभाषित करना होगा। हर दिन, चाहे लोग इसे समझें या नहीं, वे information systems से interact करते हैं — चाहे वह smartphone हो, computer हो, या दुकान के दरवाज़े का sensor हो (इस पर बाद में और बात होगी)। हर system में information प्रस्तुत की जाती है, user उसे समझता है, कभी-कभी response देता है, और फिर system उस response को process करता है। फिर system फिर से information प्रस्तुत करता है, और interaction के दौरान cycle दोहराता रहता है। cycle किसी भी point से शुरू हो सकता है: information user के समझने से बहुत पहले प्रस्तुत हो चुकी हो सकती है, या user बिना information प्रस्तुत हुए भी respond कर सकता है। flow कब या कैसे शुरू होता है, इससे फर्क नहीं पड़ता; वही cycle लागू होता है।

CatalystUI Model इसी flow के आसपास बना है। यह user और information system के बीच information कैसे flow करती है, यह बताने के लिए high-level structure देता है, तब भी जब system पारंपरिक user interface जैसा न दिखे। दूसरे शब्दों में, दुकान के दरवाज़े का sensor किसी व्यक्ति को लगभग जादुई रूप से “sense” करता हुआ लग सकता है, लेकिन information flow process को सरल बनाता है: user doorway देखता है, आगे का रास्ता पहचानता है, और detection area में चलता है। वह movement system के लिए input बन जाती है। system उसे process करता है, perceivable output के रूप में दरवाज़ा खोलता है, और user उसके पार चलकर respond करता है। थोड़ी देर बाद, system दरवाज़ा बंद कर देता है, exchange समाप्त करता है, जब तक कोई और action cycle को दोबारा शुरू न करे।

information flow के साथ-साथ, _user interface_ यह define करता है कि यह flow किसी दिए गए information system के भीतर कैसे होता है। यह तय करता है कि system input कैसे स्वीकार करता है, output कैसे पैदा करता है, और user को उससे interact करने की अनुमति कैसे देता है। क्योंकि हर system की ज़रूरतें अलग होती हैं, समय के साथ इन interactions को describe और implement करने के कई तरीके विकसित हुए हैं, जिनमें “human interfaces” (“HI”), “human-machine interfaces” (“HMI”), और “human-computer interfaces” (“HCI”) शामिल हैं। आधुनिक computing age में, इन interfaces का सबसे परिचित रूप “graphical user interface” (“GUI”) है।

जब हम अलग-अलग implementations की तुलना करते हैं, एक common pattern उभरने लगता है। बाहरी differences के बावजूद, हम तीन concepts पहचान सकते हैं जो सभी user interfaces में दिखाई देते हैं: 1) “domains,” जो data को categorize और organize करते हैं; 2) “the stack,” जो data को represent और explain करता है; और 3) “connectors,” जो data को transform, modify, और translate करते हैं। हर concept अपने आप में उपयोगी है, लेकिन मिलकर वे एक _reversible_ _system_ बनाते हैं जो पूरे interface और individual processes दोनों को describe कर सकता है। यहीं CatalystUI Model की शक्ति स्पष्ट होती है: interaction को categorization, representation, और translation में अलग करके, यह information systems को explain, debug, और understand करना आसान बनाता है।
