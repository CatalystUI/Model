# 4.7 Domains :: Multisensory

## 深入讨论

**multisensory** domain 描述的是作为统一体验的一部分，被塑造成面向多个感官的数据。它不只是同一个系统中存在多种输出。它指的是不同感官形式被连接、协调、路由或一起交付，使用户把它们作为“*一件事*”来接收的地方。

这种区别很重要，因为一个系统可以包含几种输出，却并不真正具有多感官意义。程序可以在一个地方显示图像，在另一个地方播放声音，但如果这些输出彼此无关，它们仍然是分离的沟通形式。当这些形式被有意绑定在一起或同时呈现时，多感官数据才会出现。带有同步音频的视频、把撞击声与身体反馈结合在一起的游戏事件，或通过显示器和扬声器的独立路径发送协调输出的设备，都可以属于这个 domain，因为体验取决于输出之间的关系。

多感官数据通常出现在这样一个位置：信息不再被作为孤立表示处理，而是作为协调交付处理。数据可以被合并成一个流，被分配到多个输出中，或被同时为多个设备准备。重要的特征不是所有东西都通过同一根线缆、同一个文件或同一个对象传输。重要的特征是用户把结果作为一个有意义的事件来接收。

### 理解多感官数据

理解多感官数据的一个有用方式，是考虑 **组合**、**同步** 和 **路由**。

**组合** 描述不同输出形式如何被放在一起。在视频通话中，语音、面部动作、字幕和界面反馈都可能为同一个体验做出贡献。这些部分没有一个能够完全替代其他部分。它们的意义会变得更强，因为它们被组合成一个沟通整体。

**同步** 描述这些输出如何随时间保持关联。到得太晚的声音、事件已经过去后才触发的振动，或落后于语音的字幕，都可能让体验感觉坏掉，即使每个单独输出仍然有效。多感官数据依赖时机，因为信号之间的关系常常就是意义的一部分。

**路由** 描述一个统一体验如何通过分离路径交付。系统可以把一部分输出发送到显示器，把另一部分发送到扬声器，把另一部分发送到触觉设备。这些路径在物理上可能分离，但当它们被正确协调时，用户仍然会把它们理解为一次交互。路由很重要，因为多感官数据经常必须在意义上保持统一，同时在交付上被拆分。

### 多感官意义

多感官输出通过关系表达意义。声音可以确认用户看到的内容。振动可以给用户听到的内容增加重量。字幕可以保留原本可能在语音中丢失的信息。每个部分都有自己的感官形式，但更大的意义来自这些部分如何一起工作。

这使多感官设计不同于简单添加效果。给按钮加一个声音并不自动有意义。给提醒加一次振动并不自动有帮助。当视觉动画和音频都在沟通同一个事件时，它们可以强化一次交互；但如果它们暗示不同的事情，也可能造成混乱。这个 domain 之所以有用，是因为它要求我们判断输出是在协作，还是只是共存。

多感官数据还可以比单一感官路径更有韧性地承载意义。如果一个输出被错过，另一个输出仍然可以保留部分消息。如果用户不能依赖视觉，声音可以承载重要信息。如果环境嘈杂，触觉或可见结构可以改为承载它。设计良好的多感官体验不会随机散布意义；它会有目的地分配意义。

### 多感官数据与无障碍

multisensory domain 对无障碍尤其重要，因为它帮助识别意义是否在不同感知形式之间被保留下来。当多个输出协调良好时，用户有不止一种方式理解发生了什么。当它们协调不佳时，系统表面上可能看起来可访问，却仍然把重要意义困在单一感官路径中。

一个通知如果既以视觉方式出现，又发出可听声音，并提供身体反馈，就可以用几种方式传达同一事件。这可能很有帮助，但前提是每种形式都有意义且合适。如果声音承载了视觉输出没有的信息，或者视觉输出包含其他输出无法访问的细节，那么体验仍然可能不均衡。多感官设计应该保留意图，而不仅仅是复制效果。

这也是系统必须尊重用户控制的地方。有些用户可能需要通过一种感官获得更多输出，而通过另一种感官获得更少输出。其他用户可能会关闭声音、减少运动、避免振动或依赖字幕。多感官体验在能够适配而不丢失让体验保持一致的意义时最强。

### 更广泛系统中的多感官数据

多感官数据常见于信息必须同时通过多个通道交付的系统。媒体播放可以把运动图像和声音结合成一个流。模拟器可以协调视觉、音频和身体反馈来表示现实世界事件。操作环境可以把不同类型的输出路由到不同设备，同时仍然向用户呈现一次统一交互。

这些例子说明，不能把多感官数据当作一组松散的独立 domains。输出一旦被同步、组合或路由在一起，它们之间的关系就成为信息的一部分。系统不再只是在问：“应该看到什么？”或“应该听到什么？”它在问多种感知形式应该如何一起工作，才能让用户理解一个事件。

这也解释了为什么多感官数据通常很难设计好。每种输出都有自己的限制、时机、交付方式和用户期望。把它们结合起来需要的不只是把同一条消息发到每个地方。它需要决定意义的哪一部分属于哪种形式，这些形式如何保持连接，以及如果其中一种不可用时应该发生什么。

### 多感官数据与 Domains 的目的

multisensory domain 通过描述感官沟通被协调时发生的事情，帮助完成 domain model。Symbolic data 给系统一种把意义作为表示来保存的方式。各个感官 domains 解释这种意义如何以特定方式变得可感知。Multisensory data 解释这些可感知形式如何被组合成一个更大的体验。

这正是这个 domain 必要的原因之一。没有它，每个复杂输出都只能被描述为分离的感官部分。那会错过许多真实交互的重点。电影不是作为孤立图像加孤立声音来体验的。游戏中的撞击也不总是被理解为分离的动画、分离的噪声和分离的振动。用户接收的是它们之间的关系。

简而言之，multisensory domain 描述的是被塑造成协调感官输出的信息。它帮助解释系统如何组合、同步和路由数据，使多种感知形式能够承载一个连接的意义。当多感官数据被妥善处理时，用户得到的不只是同时出现的多个输出；他们得到的是一个在相关感官之间保留意义的统一体验。
