# 4.1 Domains :: Symbolic

## 深入讨论

**symbolic** domain 描述的是数据在被提交到直接感官输出之前，以表示形式存在的状态。符号数据通过代表别的事物来承载意义。它可以描述一个值、定义一条规则、保存一条消息、识别一种关系，或指示系统某个事物应该如何表现。它的目的不是立即被感知，而是进行表示。

这使 symbolic data 在模型的上下文中非常重要。一个系统无法有意义地转换信息，除非这些信息首先 *存在*。文档、配置文件、数据格式或标记结构都可能包含意义，但这种意义以符号方式保存。系统必须按照某种预期读取它，才能对它做任何有用的事情。

符号数据不是“原始的空无”。它可以高度有组织、意义深厚，并且已经准备好被解释。一个数字可以表示尺寸，一个字符串可以表示标题，一个标签可以表示章节的开始。数据已经意味着某些东西，但它的意义仍然通过符号而不是直接经验来承载。

### 符号表示

符号之所以有效，是因为它承载了超出其直接形式的意义。名称、值、规则或定义可以代表系统之后需要理解的东西。符号本身不是最终结果；它是一种系统可以保存、传递、比较和解释的表示。符号数据依赖于一种分离：一边是被写下、存储或定义的内容，另一边是这种表示 *意在* 描述的事物。

因此，符号数据拥有直接输出所没有的力量。它可以被存储、复制、搜索、传输、编辑、验证和转换，而不要求最终体验已经存在。系统可以在产生某个事物之前先保存对它的描述。这种分离赋予软件很大一部分灵活性。

这也是精确性重要的地方。如果符号不清楚，系统也许仍然能够处理它，但意义会变得不稳定。模糊的名称、格式错误的结构或不一致的数据格式，可能在任何东西到达用户之前就已经造成混乱。符号错误很危险，因为它们常常发生得很早，然后在依赖它们的一切事物中回响。

### 符号结构

符号数据很少作为孤立的值存在。它通常出现在某种结构中，而这种结构为每个值赋予角色。配置文件可以包含键和值。文档可以包含标题和段落。命令可以按照特定顺序包含参数。意义不仅来自每个符号本身，也来自它出现的位置，以及它如何与周围的信息相关联。

这就是为什么同一个符号可以承载不同的意义。一个值、名称或短语不会仅仅因为存在就解释自己；它从周围上下文中获得角色。结构告诉系统每一块符号数据应该如何被理解，无论它是在定义属性、识别关系、设置条件，还是描述更大整体的一部分。

良好形成的符号结构为系统提供可靠的解释路径。它允许数据被解析、检查、转换，并连接到后续行为。糟糕的符号结构会迫使系统猜测、推断，或完全拒绝这些数据。以 CatalystUI 的术语来说，符号结构是清晰性最早开始或破裂的地方之一。

### 符号解释

当系统知道如何解释符号数据时，符号数据才变得有用。解释把表示连接到预期意义。解析器可以读取文件格式。模式可以定义有效字段。命令处理器可以确定一个短语描述了什么动作。没有解释，符号数据仍然可以存在，但系统没有可靠的方式对它采取行动。

这就是为什么符号数据如此接近意图。开发者可以通过代码描述行为。用户可以通过设置改变行为。文档可以通过文本保存思想。在每种情况下，符号形式都允许意义被表达，而不需要直接操作最终结果。系统接收一个表示，解释它，然后用它来引导接下来发生的事情。

符号交互可能不像直接操作那样即时，但它通常提供更强的控制力。书面命令可以被精确重复。配置文件可以被版本化。结构化文档可以被转换成许多不同的输出。符号数据为系统和用户都提供了稳定的参照点。

### 符号数据与无障碍

符号数据在无障碍中扮演重要角色，因为它以一种可以被适配的形式保存意义。当信息只作为最终呈现存在时，系统解释、调整大小、搜索、翻译或重新组织它的能力可能有限。当底层符号意义仍然可用时，系统就有更多选择，可以以用户能够接收的方式呈现这种意义。

结构化文档比扁平化的文字图片更容易导航。带有有意义标签的控件，比一个目的只存在于外观中的控件更容易暴露给辅助技术。带有真实关系的数据表，比一张行和列的图片更容易重新解释。在每种情况下，符号数据都保护了呈现背后的意义。

这并不会让符号数据自动具有无障碍性。符号可能模糊、不完整、标签错误，或与它本该表示的事物脱节。但当符号意义清楚并被保留下来时，系统就获得了在不丢失目的的情况下转换信息的能力。

### 模型中的符号数据

symbolic domain 给 CatalystUI 一种方式，用来描述信息在成为直接面向用户的体验之前的状态。意义可以在这里被存储、命名、排列和准备。这包括文件、命令、格式、元数据、设置、源代码、标记，以及系统可以解释的其他表示形式。

它的重要性很容易被忽略，因为符号数据往往生活在结果背后。用户也许永远不会看到让体验成为可能的文件格式、模式、解析器或内部表示。然而这些符号形式塑造了系统能够理解什么、能够产生什么，以及能够多忠实地在转换之间保留意义。

简而言之，symbolic domain 描述的是作为表示的信息。它不是由用户如何感知它来定义的，而是由系统在直接呈现之前如何保存和理解意义来定义的。当符号数据被妥善处理时，交互的其余部分就有了更清晰的基础可以建立。
